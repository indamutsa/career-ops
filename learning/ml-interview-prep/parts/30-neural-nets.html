Part C · Deep learning · Module 30

Neural networks Module 21's logistic regression scores a fraud transaction with p = σ(w·x + b) — one straight decision boundary, forever. A neuron is f(w·x + b) for some non-linear f; stack several of them and the boundary can curve. On this page one small fraud network, scored and trained by hand, carries every idea: activations, backpropagation, initialisation, normalisation, residuals.

From a straight boundary to a curved one — the neuron

logistic regression (module 21) → one neuron → several neurons in parallel, a layer → layers in sequence, a network
WhatA neuron computes f(w·x + b): a weighted sum of its inputs, plus a bias, passed through a non-linear function f.
WhyA single linear score can only separate classes with a straight line (or hyperplane); f lets a network bend that boundary.
Where in MLEvery layer of every feedforward network, CNN and transformer MLP block is neurons computed this way.

Module 21 fit a fraud classifier as p = σ(w·x + b): multiply each feature by a learned weight, add a bias, squash with the sigmoid σ. Its decision boundary — where p = 0.5 — is exactly where w·x + b = 0, a straight line (a hyperplane in higher dimensions), because w·x + b is linear in x. No choice of w or b can bend it.

A neuron is the same computation with the squashing function generalised: f(w·x + b) for some non-linear f. If f is still σ, one neuron is logistic regression — nothing new happened yet. The power only appears once several neurons are combined, which is section 30.2.

?The logit — the number before the squashing

Call z = w·x + b the logit: the raw score a neuron produces before any non-linearity touches it. It is any real number — a logit of 4.2 means "strongly this class", −1.3 means "probably not". Module 21's w·x + b was already a logit; module 13's cross-entropy loss is defined to take logits, not probabilities, because the fused sigmoid/softmax-plus-cross-entropy computation is numerically stable and the separated version is not. Section 30.4 computes a real logit for a real transaction.

Interview takeawayA neuron is f(w·x + b); with f = σ it collapses to logistic regression. The non-linearity, not the neuron, is what buys expressive power.

Stacking neurons: a hidden layer, and the network for this page

WhatA layer is several neurons computed in parallel from the same input; a network is layers run in sequence, each feeding the next.
WhyOne neuron draws one straight cut through feature space. Several neurons, combined by a further neuron, can draw a curve.
Where in MLFully-connected (feedforward) layers are the default architecture whenever the input has no special structure — and are still two-thirds of a transformer's parameters.
Why stacking finds structure nobody programmed

Recognising a face: the first layer notices edges. The second combines edges into corners and curves. The third combines those into eyes and noses. The fourth combines those into faces. Nobody wrote "an eye is two curves and a dark circle" — the hierarchy is what the network discovers because it is the cheapest way to reduce the loss. That learned feature hierarchy is the one thing deep learning brought that classical ML did not have.

The fraud features from module 12.6 were the transaction amount and a merchant-mismatch flag. Standardise the amount against the training distribution the way module 12.6 standardised area and bedrooms, and call the two inputs x1 (standardised amount) and x2 (mismatch flag, 0 or 1). This page's network is small enough to compute by hand and still shows every mechanism:

inputs: x = [x1, x2]  →  hidden layer: h1, h2 (ReLU)  →  output: p (sigmoid)
hidden neuron 1: w11 = 0.8, w12 = 1.5, b1 = −1.0
hidden neuron 2: w21 = −0.5, w22 = 2.0, b2 = 0.3
output neuron: wo1 = 0.9, wo2 = −0.6, bo = −1.0
Nine numbers a network like this learns from data — six weights and three biases. Sections 30.4-30.6 compute what they produce for one real transaction (forward pass) and how training would nudge them (backward pass, then one update).
what each symbol is wijweight from input j into hidden neuron i b1, b2each hidden neuron's own bias wo1, wo2weights from the two hidden neurons into the output neuron

The transaction we will score is the flagged, roughly-€1,240 transaction from module 12.9. After standardisation it lands at x1 = 2.6 (a large amount — a standardised score this high says the amount sits well above the typical transaction) and x2 = 1 (its merchant category was flagged as mismatched, the same flag module 12.6 correlated with larger amounts).

Interview takeawayA hidden layer is several neurons sharing one input; a network is layers in sequence. Depth lets each layer reuse the previous layer's discovered features instead of re-deriving them.

Activations — the one-line reason you need one

Compose two linear layers with no non-linearity between them: W2(W1x + b1) + b2 = (W2W1)x + (W2b1 + b2). That is a single linear layer with different weights. Without a non-linearity, a thousand-layer network is exactly as expressive as one layer. The activation function f from 30.1 is what breaks that collapse.

ActivationShapeWhy it exists / why it fell out of use

This page's hidden neurons use ReLU: h = max(0, z). Its gradient is exactly 1 where z > 0 and exactly 0 where z < 0 — a fact 30.5's backward pass uses directly.

?Dead ReLU — what happens when z never crosses zero

Suppose hidden neuron 2's logit had come out z2 = −1.0 instead of positive. ReLU gives h2 = max(0, −1.0) = 0, and because its gradient is 0 for negative inputs, every gradient that would flow into w21, w22 and b2 during backpropagation is also exactly 0 — the weights feeding that neuron never update again. If a neuron's logit is negative for every example in the training set, it is permanently dead. This usually comes from too high a learning rate or a badly scaled initialisation (30.7); the fixes are Leaky ReLU, a lower learning rate, or a smooth variant such as GELU.

Interview takeawayReLU's gradient is 1 on the positive side and exactly 0 on the negative side — the source of both its trainability and the dead-unit failure mode.

The backward pass — backpropagation

WhatThe chain rule applied layer by layer in reverse, so every weight's effect on the loss is computed in one backward sweep.
WhyA network can have millions of weights; recomputing the whole forward pass separately for each one would be millions of times slower.
Where in MLEvery training step, in every framework, for every architecture in this book.
?Why reverse, and what it costs

The network is a composition: loss = L(fo(fh(x))). The chain rule gives every weight's gradient as a product of local derivatives along the path from that weight to the loss, and those products share almost all their factors. Computing right-to-left — starting at the loss and moving back — computes each shared factor once and reuses it for everything below. That is reverse-mode automatic differentiation, and its cost is roughly one extra forward pass, however many parameters the network has.

Forward-mode differentiation costs one pass per input variable instead; reverse-mode costs one pass per output. A network has millions of parameters feeding one scalar loss, so reverse-mode wins by a factor of millions — the entire reason training deep networks is computationally feasible.

The cost is memory: every intermediate activation from the forward pass (every z1, h1, etc. computed in 30.4) must be kept until the backward pass consumes it. That is why activation memory, not parameter memory, dominates training footprint — and why gradient checkpointing exists: discard some activations and recompute them on the way back, trading compute for memory.

Suppose this transaction is later confirmed fraud: true label y = 1. Binary cross-entropy loss (module 13's cross-entropy, using natural log rather than module 13's log base 2 — training losses use natural log because it makes the gradient below cancel exactly; the choice of log base only rescales the loss by a constant, it does not change what gradient descent does) is:

L = −[y ln p + (1−y) ln(1−p)] = −ln(0.673) ≈ 0.396 nats  (since y = 1)
∂L/∂zo = p − y = 0.673 − 1 = −0.327
Module 21 showed this exact cancellation for logistic regression's own gradient, (p−y)x — σ's derivative cancels against cross-entropy's derivative. It is the same neuron computation, so the same cancellation applies at this output neuron.
∂L/∂wo1 = ∂L/∂zo · h1 = −0.327 × 2.58 = −0.844
∂L/∂wo2 = ∂L/∂zo · h2 = −0.327 × 1.0 = −0.327
∂L/∂bo = ∂L/∂zo = −0.327
Each output weight's gradient is the upstream signal (−0.327) times whatever hidden activation it multiplied on the way forward — the chain rule's local-derivative-times-upstream-signal pattern.
∂L/∂h1 = ∂L/∂zo · wo1 = −0.327 × 0.9 = −0.294
∂L/∂z1 = ∂L/∂h1 · ReLU′(z1) = −0.294 × 1 = −0.294  (z1 = 2.58 > 0, so ReLU′ = 1)
∂L/∂w11 = ∂L/∂z1 · x1 = −0.294 × 2.6 = −0.765
∂L/∂w12 = ∂L/∂z1 · x2 = −0.294 × 1 = −0.294
∂L/∂h2 = ∂L/∂zo · wo2 = −0.327 × (−0.6) = 0.196
∂L/∂z2 = ∂L/∂h2 · ReLU′(z2) = 0.196 × 1 = 0.196  (z2 = 1.0 > 0, so ReLU′ = 1)
∂L/∂w21 = 0.196 × 2.6 = 0.510  ·  ∂L/∂w22 = 0.196 × 1 = 0.196
Every gradient traces back to the single upstream number −0.327, multiplied by whichever weight and activation sat on its path — exactly the "reuse the shared factor" idea from the deep box above. If z₁ or z₂ had been negative, ReLU′ would be 0 here and every downstream gradient in that branch would vanish, as 30.3's dead-ReLU aside described.
Nothing vanished here — on purpose

This network has one hidden layer, so the chain from loss to w11 is only two multiplications long, and both ReLU′ factors happened to be 1. Stack twenty such layers and the gradient at the bottom is a product of twenty such factors — section 30.7 is what happens when that product is not so well-behaved.

Interview takeawayBackpropagation is not a separate learning algorithm — it computes gradients via the chain rule, reusing shared factors right-to-left. Gradient descent is what does the learning.

One parameter update — closing the loop

Module 14's update rule was θ ← θ − η∇L: subtract the learning rate times the gradient. Apply it to wo1 with η = 0.1:

wo1 ← wo1 − η·∂L/∂wo1 = 0.9 − 0.1×(−0.844) = 0.9 + 0.0844 = 0.984
wo1 ties hidden neuron 1 — the one that fired on the large standardised amount — to the output. Because this transaction really was fraud and the network under-predicted (0.673 rather than closer to 1), the gradient step increases that weight, so a similarly large-amount pattern will push the output higher next time.
what each symbol is ηthe learning rate from module 14 — how much of the gradient to subtract θ ← θ − η∇Lthe same update rule, applied here to one weight instead of module 14's scalar example

Every other weight and bias updates the same way, using the gradients computed in 30.5. Repeat this over every labelled transaction in the training set, many times, and the nine numbers in 30.2 converge toward values that separate fraud from non-fraud along a curve rather than a straight line.

Interview takeawayTraining is forward pass → loss → backward pass → θ ← θ − η∇L, repeated. Nothing else is happening underneath the frameworks.

Making depth trainable: initialisation and vanishing gradients

WhatInitialisation is the random starting values of the weights (like 30.2's nine numbers, before any training); vanishing/exploding gradients is what happens when many layers' derivatives multiply together.
WhyA bad start or too many small (or large) multiplicative factors can stop a deep network from learning at all.
Where in MLEvery deep network's first step, and the standing reason very deep plain networks were hard to train before residuals and normalisation.

Two failure modes bracket the problem. Initialise every weight to zero and every neuron in a layer computes the same thing, receives the same gradient, and stays identical forever — symmetry never breaks. Initialise too large or too small and the activation variance multiplies layer over layer, so by layer 20 it has either exploded or collapsed to nothing. 30.2's weights (0.8, 1.5, −1.0, …) are small, non-zero, and of mixed sign for exactly this reason.

The fix is to choose the initial weight variance so the signal's scale survives the layer. If a neuron sums n inputs and the output variance should match the input variance, the weight variance must scale like 1/n:

  • Xavier/Glorot, variance 1/n (or 2/(nin+nout)) — derived for symmetric activations like tanh.
  • He/Kaiming, variance 2/n — the factor of 2 compensates for ReLU zeroing about half the inputs and therefore halving the variance. Use it whenever the activation is ReLU-like, which today is nearly always — including the hidden layer in 30.2.
?Where the vanishing-gradient product comes from

30.5's backward pass multiplied exactly two factors to reach w11: ∂L/∂zo · wo1 · ReLU′(z1). An L-layer network multiplies L such factors to reach its first layer. Sigmoid's derivative is σ(1−σ), which maxes out at 0.25; stack ten sigmoid layers and even in the best case the gradient is multiplied by 0.25 ten times — about 10⁻⁶ — so early layers receive essentially nothing. ReLU's gradient is exactly 1 on the positive side, which is why it does not shrink that product — but nothing stops the weight factors in the same product from being systematically above or below 1, which is where exploding or vanishing gradients still come from even with ReLU. Careful initialisation narrows that risk; normalisation (30.9) and residual connections (30.8) are what actually solved it at real depth.

Modern architectures lean on initialisation less because normalisation layers and residuals absorb scale problems — but it still bites: large transformers scale the initialisation of the residual projections by 1/√(2·n_layers) so the residual stream's variance does not grow with depth, and getting that wrong produces an early loss spike.

Interview takeawayZero init breaks symmetry the wrong way; badly-scaled init makes variance explode or collapse across depth. Match the weight variance to the activation to keep signal scale roughly constant layer to layer.

Residual connections — the one-line reason they work

A plain deep network's gradient is a long product of layer Jacobians (module 11) — 30.7's failure mode, run to its conclusion. Products of factors below 1 vanish; above 1 they explode, and there is no stable regime as depth grows.

A residual block computes y = x + f(x). Differentiate:

∂y/∂x = 1 + f′(x) the gradient has a path multiplied by exactly 1, all the way down

The identity term guarantees an unimpeded route for the gradient from the loss back to any layer, regardless of what the blocks in between do to it. That is the whole mechanism, and it is worth being able to write down rather than describe.

The second framing, from the ResNet paper: it is easier to learn a small correction to the identity than to learn the identity itself from scratch. A block with nothing useful to add can simply output ≈0 and be harmless, so adding depth cannot make the model worse — precisely the pathology observed before residuals, where 56-layer plain networks did worse than 20-layer ones on training error, ruling out overfitting as the explanation.

Interview takeaway∂(x + f(x))/∂x = 1 + f′(x): the +1 gives every layer an unimpeded gradient path, which is why networks beyond ~20 layers became trainable.

Normalisation — BatchNorm vs LayerNorm

WhatRescale a layer's outputs to zero mean and unit variance before the next layer sees them, then let two learned parameters rescale again.
WhyIt smooths the loss landscape, which lets training use a higher learning rate — the original "reduces internal covariate shift" explanation did not survive scrutiny; see below.
Where in MLAlmost every modern network has a normalisation layer somewhere between its linear layers.
BatchNorm

Normalises across: the batch, per feature — many transactions' hidden activation 1, together.

Effect: unstable below a batch of roughly 16, broken at batch size 1; uses running statistics at inference instead of batch statistics, a train/inference split that is a known source of bugs.

Use when: CNNs and vision, with reliably large batches.

LayerNorm

Normalises across: the features of one example — this network's own h1 and h2, together, for a single transaction.

Effect: independent of batch size and identical at train and inference — no running-statistics mismatch.

Use when: variable-length sequences, small or per-device batches — which is every transformer.

The interview answer for "why do transformers use LayerNorm" is the three effects above: sequences pad to a common length, so BatchNorm's per-feature statistics get contaminated by padding; per-device batch sizes in large-model training are often small; and the train/inference discrepancy is a bug factory. LayerNorm has none of those problems.

?RMSNorm, pre-norm, and the covariate-shift myth

RMSNorm, used in Llama-family models, goes further by dropping the mean subtraction entirely — it turns out the re-centring contributes little, and removing it is cheaper. Pre-norm, placing the normalisation inside the residual branch rather than after it (post-norm), is standard now because post-norm requires careful learning-rate warmup and is much harder to train at real depth.

One correction worth having ready: the original BatchNorm paper attributed its success to reducing "internal covariate shift". Later work showed that story is mostly wrong — the real mechanism is that it smooths the loss landscape, allowing higher learning rates. Knowing that the paper's own explanation did not survive scrutiny is a good signal in an interview.

Interview takeawayBatchNorm normalises across the batch and depends on batch size; LayerNorm normalises across the features of one example and does not — which is why every transformer uses it.

Dropout and universal approximation

WhatDropout randomly zeroes a fraction of activations during training and does nothing at inference. Universal approximation says a wide-enough single hidden layer can approximate any continuous function on a bounded region.
WhyDropout stops any one unit from becoming indispensable; universal approximation is the existence proof behind "why does a network like 30.2's work at all".
Where in MLDropout: fine-tuning and smaller models, less central in huge-data transformer training. Universal approximation: purely theoretical background for the "why go deep" question in 30.11.

If any given unit may vanish on any training step, the network cannot build a fragile chain that depends on one specific unit being present — it is forced into redundant, distributed representations. Applied to 30.2's hidden layer, dropout would zero h1 or h2 outright on some training steps.

?Inverted dropout and MC dropout

Drop 50% of units during training and the expected sum reaching the next layer halves. At inference nothing is dropped, so the sum would be twice what the network trained on. Frameworks fix this with inverted dropout: divide the surviving activations by the keep probability during training, so inference needs no adjustment and is simply the identity — which is also why forgetting to switch a framework's training/inference mode leaves dropout active at inference and makes predictions non-deterministic and worse.

Running the same random-zeroing mechanism deliberately at inference, many times, and looking at how much the predictions vary is MC dropout — a cheap uncertainty estimate built from the same trick.

Universal approximation is an existence theorem only: it says a wide-enough single hidden layer exists, not that it is findable by gradient descent, affordable, or data-efficient. Depth achieves the same functions with exponentially fewer units by reusing structure — the hierarchy from 30.2's face analogy — rather than representing every combination directly.

Interview takeawayDropout regularises by preventing co-dependence between units; universal approximation proves a shallow network could work, not that it is the practical choice — depth wins on unit count and data efficiency.

Questions

BASICWhy do neural networks need non-linear activation functions?
Because a composition of linear functions is itself linear. Without a non-linearity, a hundred-layer network has exactly the expressive power of a single linear layer.

The algebra takes one line: W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂). The product W₂W₁ is just another matrix. Depth buys nothing.

The non-linearity is what lets each layer carve the space in a way the next layer can build on, which is where the hierarchy of features comes from — edges to shapes to objects, module 30.2's face example.

A worthwhile addition: the non-linearity does not have to be complicated. ReLU is a hinge, the simplest non-linear function you could write down, and it is enough — it is what 30.2's hidden layer uses. What matters is not the sophistication of the function but that it breaks linearity while keeping a usable gradient.

MIDWhy did ReLU replace sigmoid, and what did it cost?
ReLU has gradient exactly 1 on the positive side, so gradients do not vanish through depth, and it is far cheaper to compute. The cost is dead units and a non-zero-centred output.

The problem with sigmoid: its derivative is σ(1−σ), which maxes out at 0.25 and approaches zero at both ends. Stack ten layers and even in the best case the gradient is multiplied by 0.25 ten times — about 10⁻⁶. Early layers receive essentially nothing and never learn. Saturated units make it far worse.

What ReLU fixes: gradient is 1 for x > 0, so the product of Jacobians does not shrink through the positive path — exactly why 30.5's backward pass hit ReLU′ = 1 twice without losing signal. It is also a comparison and a select rather than an exponential, which matters at scale, and it produces genuinely sparse activations, since roughly half the units output zero.

What it costs: the dead ReLU problem from 30.3 — a unit whose pre-activation is negative for every input has zero gradient forever and is permanently removed from the model. Usually caused by too high a learning rate driving a large negative bias. Mitigations are Leaky ReLU, a lower learning rate, better initialisation, or a smooth variant. Its outputs are also not zero-centred, which biases the gradients of the following layer — one of the reasons normalisation layers help.

Where things landed: GELU and SiLU are the modern defaults for transformers. They are smooth, allow small negative values, and give a consistent small improvement. The gain is real but modest — ReLU versus sigmoid was a step change, GELU versus ReLU is a refinement.

Trap

ReLU is not differentiable at exactly 0. In practice frameworks define the subgradient there as 0 and it never matters, since hitting exactly 0.0 in floating point is vanishingly unlikely.

MIDIf one hidden layer can approximate any function, why go deep?
Because the theorem says a wide-enough single layer exists, not that it is findable, affordable, or data-efficient. Depth achieves the same functions exponentially more cheaply.

Three separate gaps between the theorem and practice:

  • Width. "Wide enough" can mean exponentially many units in the input dimension. There are functions a deep network represents with a polynomial number of units that a shallow one needs exponentially many for — this is proved for several function classes, not just conjectured.
  • Optimisation. The theorem is about existence, not about whether the gradient-descent loop from 30.6 finds it. A function that exists somewhere in a shallow network's parameter space is of no use if gradient descent cannot reach it.
  • Data. A very wide shallow network has enormous capacity and no useful structural prior, so it needs far more data to generalise.

The deeper point is about compositional structure: real problems are hierarchical, the way 30.2's face example builds edges into corners into eyes into faces. A deep network's architecture matches that structure, so each layer reuses the previous layer's work. A shallow network has to represent every combination directly, without reuse — which is exactly where the exponential blow-up comes from.

MIDWhy do transformers use LayerNorm instead of BatchNorm?
Because batch statistics are the wrong thing to normalise over for variable-length sequences, and because BatchNorm behaves differently at training and inference time. LayerNorm has neither problem.
  • Variable length. Sequences are padded to a common length. BatchNorm's per-feature statistics are then computed over real tokens and padding together, so the normalisation depends on how much padding happened to be in the batch. That is noise injected by the batching strategy.
  • Batch-size dependence. Per-device batch sizes in large-model training are small. BatchNorm's estimates get noisy below roughly 16 and are meaningless at 1, which rules it out for inference on a single sequence.
  • Train/inference mismatch. BatchNorm uses batch statistics while training and stored running averages at inference. Two different functions, and a well-known source of bugs when the running statistics are stale or the model is switched into the wrong mode. LayerNorm computes the same thing in both.
  • Distribution. BatchNorm needs cross-device synchronisation to be correct under data parallelism. LayerNorm is purely per-example and per-device.

Where it went next, worth adding: modern models mostly use RMSNorm, which drops the mean subtraction and normalises only by the root mean square. Slightly cheaper, and empirically just as good — the re-centring was carrying little of the benefit. And placement matters as much as the choice: pre-norm, with the normalisation inside the residual branch, is standard now because post-norm requires careful warmup and is much harder to train at depth.

SENIORExplain backpropagation to someone who knows calculus but not ML.
It is the chain rule applied in reverse through the network, with intermediate results cached so that every parameter's gradient is obtained in one backward sweep rather than one sweep per parameter.

Setup. The network is a composition: loss = L(f₃(f₂(f₁(x)))). You want ∂L/∂w for every weight in every layer. The chain rule gives each one as a product of local derivatives along the path from that weight to the loss — exactly the products computed for w11, wo1 and the rest in 30.5.

The insight is the ordering. Those products share almost all their factors. If you compute right-to-left — starting at the loss and moving back — you compute each shared factor once and reuse it for everything below. 30.5's single number, ∂L/∂zo = −0.327, is exactly that shared factor: reused for every weight in the output layer, then propagated further back to reach the hidden layer's weights. That is reverse-mode automatic differentiation, and its cost is roughly one forward pass regardless of how many parameters there are.

Why reverse and not forward: forward-mode costs one pass per input variable; reverse-mode costs one pass per output. A network has millions of parameters and one scalar loss, so reverse-mode wins by a factor of millions. This asymmetry is the entire reason training deep networks is computationally feasible.

What it costs: memory. Every intermediate activation from the forward pass must be kept until the backward pass consumes it, which is why activation memory, not parameter memory, dominates training footprint — and why gradient checkpointing exists, trading recomputation for memory.

What I would add at the end: backprop is not a learning algorithm. It computes gradients. The learning is gradient descent (30.6), and the two get conflated constantly.

Trap

"Is backprop biologically plausible?" No, and it is a fair thing to say — it needs symmetric weights for the backward pass and a global error signal, neither of which the brain appears to have. It is an engineering method, not a model of neuroscience.

SENIORWhy do residual connections make deep networks trainable?
Because the derivative of x + f(x) is 1 + f′(x). The identity term gives the gradient an unimpeded path back to every layer, so the long product of Jacobians can no longer collapse to zero.

Without residuals, the gradient at layer 1 of an L-layer network is a product of L Jacobians — the same kind of product 30.5's backward pass computed for two layers. If their typical magnitude is even slightly below 1, the product decays exponentially in depth and early layers stop learning. Slightly above 1 and it explodes. There is no stable regime as depth grows.

With residuals, each block contributes (1 + f′) instead of f′. Expanding the product gives a sum over all paths through the network, including the path that skips every block and is multiplied by exactly 1. That path cannot vanish, so gradient always reaches the bottom.

The second, complementary reason from the original paper: the empirical problem was that a 56-layer plain network had higher training error than a 20-layer one. That rules out overfitting — deeper networks were failing to optimise at all. A residual block only has to learn a correction to the identity, so a useless block can output ≈0 and cost nothing, which means adding depth can no longer hurt.

The framing worth adding: a residual network behaves somewhat like an ensemble of many shallower paths of varying length rather than one very deep chain, which explains why ResNets are robust to deleting individual layers at test time — something a plain deep network absolutely is not.

In transformers this shows up as the residual stream: every attention and MLP block reads from it and writes an increment back, and it runs unbroken from the embedding to the output. That is why interpretability work can talk about blocks "writing into" the stream, and why the initialisation of the residual projections is scaled down by depth to stop the stream's variance growing.
