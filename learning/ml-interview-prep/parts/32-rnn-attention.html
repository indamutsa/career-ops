Part C · Deep learning · Module 32

RNN, LSTM and the road to attention This module exists to make the transformer inevitable. Attention was not invented in 2017 — it was invented in 2014 as a patch for a specific failure in sequence-to-sequence models. If you can tell that story, "why transformers?" stops being a memorised answer and becomes an argument. One running example carries it: a single customer's own transaction history, the case from module 70 where "the pattern of the last N events" is the fraud signal a single transaction's features cannot see.

The problem sequences pose

WhatA feed-forward fraud model scores one transaction using only that transaction's own features. A sequence model scores it using that transaction plus a memory of every earlier transaction from the same customer.
WhySome fraud patterns only exist across rows — module 70 names this directly as a "sequence" feature: "a small-value test transaction followed by a large one." No single row contains that pattern.
Where in MLAny data with order and cross-step dependence — transaction histories, sentences, audio, click streams.

Take one customer's last four transactions, in order:

#amountmerchant categorygap since previousnote
1€40groceries— (window start)ordinary spend
2€35groceries3 daysordinary spend, same category
3€20electronics5 hoursnew category, unusually small amount
4€900electronics12 minutessame new category, 45× transaction 3's amount, arrives fast

Transaction 4 in isolation is not obviously fraud — plenty of legitimate €900 electronics purchases exist, and module 12's base rate already says P(fraud) = 0.005 for any transaction picked at random. What makes this sequence suspicious is transaction 3: a small "test" charge in a category this customer has never used, followed minutes later by a large charge in that same new category. That is exactly the pattern module 70 names — a cheap probe, then the real charge — and it is invisible to a model that looks at transaction 4 alone. Seeing it requires carrying information from row 3 into the scoring of row 4.

The analyst with one index card

You are a fraud analyst reading this customer's transaction log one line at a time, and you are allowed to keep only one index card of running notes. After every line you may rewrite the card, but you can never flip back to earlier lines. By transaction 50 the card holds an increasingly blurry compression of transactions 1–49, and the details of transaction 2 are simply gone.

That index card is the hidden state. Its finite size is the entire story of this module — and, later, the entire reason attention had to be invented.

The recurrent answer to "carry information forward": process one transaction at a time, and keep a hidden state vector that summarises everything seen so far. 32.2 makes that arithmetic concrete on these same four rows.

The hidden-state recurrence

WhatAt each step, combine the previous hidden state with the current input through the same weights, then squash with tanh.
WhyIt gives the model exactly one number line's worth of "memory" that updates every row, instead of no memory at all.
Where in MLThe core update of every RNN, LSTM and GRU — everything in this module through 32.4 is a variation on this one line.
ht = tanh(Wh ht−1 + Wx xt + b)the same weights at every timestep — parameter sharing across time, exactly as convolution shares across space
?What each symbol is before we substitute numbers

xt is transaction t turned into numbers. ht−1 is the index card as it stood before this transaction — everything the model has retained about transactions before t. Wh and Wx are the same two learned weights reused at every single step; b is a learned offset. tanh squashes the result into (−1, 1) so the hidden state cannot grow without bound as more transactions arrive.

For this worked example, use two features per transaction: the amount scaled to amount ÷ 1000 (purely so the numbers stay in the range tanh responds to, the same reasoning behind standardising features in module 10.9 — it changes no information, only the units), and a flag category_changed that is 1 when the merchant category differs from the previous transaction and 0 otherwise. Suppose training has already converged to small weights Wh = 0.5, Wx = [2, 1.5] (one weight per feature), b = 0, and the index card starts empty: h0 = 0.

x1 = 0.040 (€40, no category change)
h1 = tanh(0.5(0) + 2(0.04) + 1.5(0) + 0) = tanh(0.0800) = 0.0798
x2 = 0.0350 (€35, still groceries)
h2 = tanh(0.5(0.0798) + 2(0.035) + 1.5(0) + 0) = tanh(0.1099) = 0.1095
x3 = 0.021 (€20, groceries → electronics)
h3 = tanh(0.5(0.1095) + 2(0.02) + 1.5(1) + 0) = tanh(1.5948) = 0.9209
x4 = 0.90 (€900, still electronics)
h4 = tanh(0.5(0.9209) + 2(0.9) + 1.5(0) + 0) = tanh(2.2605) = 0.9785
h barely moves across the two ordinary grocery transactions (0.08 → 0.11), then jumps at the category switch (0.11 → 0.92) and stays near its ceiling once the large same-category charge follows (0.92 → 0.98). The hidden state is tracking exactly the two-step pattern module 70 names, without ever being told "test transaction" or "large follow-up" as a rule.
what each symbol is htthe index card after transaction t — one number, bounded between −1 and 1 xttransaction t as two numbers: scaled amount, category-changed flag Wh, Wxthe same two weights reused at every step — nothing is relearned per transaction tanhsquashes any real number into (−1, 1), so h stays bounded no matter how many transactions arrive

Interpretation: the recurrence lets transaction 4's score depend on transaction 3, without transaction 4's own features ever encoding "was there a small test charge recently." That dependency lives entirely in h3, carried forward into the computation of h4.

When to use it: whenever a row's correct label depends on what came before it for the same entity, and a fixed-size per-row feature vector cannot encode "before." The honest limit is exactly the index-card analogy: this h is one number here, and even at realistic sizes (dozens to hundreds of numbers) it is still a fixed-size summary that has to compress an arbitrarily long history. 32.3 shows what that compression costs over long distances.

Interview takeawayAn RNN turns "remember everything relevant so far" into "compress everything so far into one fixed-size vector, updated with the same weights every step."
hidden-state recurrence → same weight matrix multiplied every step → backpropagation through time multiplies that same matrix once per step → repeated multiplication is exponential → vanishing or exploding gradients

Why plain RNNs fail: the gradient over time

WhatTraining an RNN backpropagates through every timestep, and the same weight matrix gets multiplied in at each one.
WhyRepeated multiplication by the same quantity is exponential, so the learning signal for a distant dependency can vanish before it reaches the weights that need it.
Where in MLAny RNN trained on sequences longer than a few dozen steps; the reason LSTM/GRU exist.

Training uses backpropagation through time — unroll the network across timesteps and apply the chain rule, exactly as in module 30.5. But now the depth is the sequence length, and crucially the same matrix Wh is multiplied in at every step.

∂ht/∂hk = ∏ Whᵀ diag(tanh′)
a product of t−k nearly identical terms, one per step between k and t
what each symbol is ∏multiply one term per timestep between k and t Whᵀthe same recurrent weight matrix from 32.2, transposed for the chain rule diag(tanh′)a diagonal matrix holding the tanh derivative computed at that step's h — how much that step's squashing shrinks or preserves a gradient passing through it

Repeated multiplication by the same thing is exponential. If the relevant eigenvalue of Wh is below 1, gradients decay to nothing over 20–30 steps — vanishing. If above 1, they explode. Make this concrete on the customer's history: if the effective shrink factor per step here is 0.9, and the transaction that actually explains today's fraud judgment sits 50 transactions back — the same "by transaction 50" distance from the index-card analogy in 32.1 — the surviving gradient is

0.9⁵⁰ ≈ 0.005the same order of magnitude as module 12's fraud base rate itself — a coincidence worth sitting with

A gradient of 0.005 is not a weak nudge toward learning that transaction 1 mattered; it is indistinguishable from the noise floor. The model would need a gradient at that distance strong enough to overrule the prior that any given transaction is fraud with probability 0.005 — and 0.9⁵⁰ has already shrunk to roughly that same size before it even reaches the relevant weights. The signal is not weak, it is functionally absent.

Two distinct failure modes with very different remedies: exploding gradients have a cheap fix — gradient clipping, rescale the gradient whenever its norm exceeds a threshold. Vanishing has no such fix, which is what LSTM was designed for.

Interview takeawayThe exponential comes from multiplying the same matrix once per timestep — state the product form, not just "gradients vanish," and be ready to say why clipping only rescues the exploding side.

LSTM and GRU: gates as an additive path

WhatA second state — the cell state — updated by addition and gated multiplication instead of a fresh matrix multiply every step.
WhyAddition does not compound exponentially the way repeated matrix multiplication does, so a signal can survive far more steps.
Where in MLAny RNN task where the relevant history is longer than a few dozen steps — which, per 32.3, is most of them.
Cell state mid

A second state vector that runs along the sequence and is modified by addition, not by repeated matrix multiplication.

A conveyor belt running the length of the customer's transaction log. Gates drop things on and take things off, but the belt itself just keeps moving.

This is the same trick as a residual connection: create a path where the gradient is multiplied by roughly 1, so it survives many steps.

Forget gate mid

A sigmoid vector that decides, per dimension, how much of the previous cell state to keep.

Initialise its bias positive (often 1.0) so it starts near "remember everything" — a small, real trick that measurably helps training.

Input gate mid

Decides how much of the new candidate value to write into the cell state.

Output gate mid

Decides how much of the cell state to expose as this step's hidden state.

The split between what is stored and what is shown is the design's cleverest part — the LSTM can hold something for later without acting on it now.

Bidirectional RNN basic

Run one RNN forward and another backward, concatenate the states.

Only valid when the whole sequence is available. Useless for generation or for streaming inference — a distinction that survives into BERT vs GPT.

Carry the fraud story into the gates. Say that at transaction 3 — the category-switch, small "test" charge — the LSTM's cell state already registers mild suspicion on one dimension: c3 = 0.7. At transaction 4, the gates (already trained, values chosen here small and hand-computable) read forget f = 0.9 (keep most of that suspicion), input i = 0.8, candidate value c̃ = 0.95 (a strong new signal from the large, fast follow-up charge), and output o = 0.85.

c4 = f ⊙ c3 + i ⊙ c̃ = 0.9(0.7) + 0.8(0.95) = 0.63 + 0.76 = 1.39
the cell state is not squashed by tanh the way the hidden state is, so it can exceed 1 — it is a running accumulator of evidence, not a bounded summary.
h4 = o ⊙ tanh(c4) = 0.85 × tanh(1.39) = 0.85 × 0.883 = 0.751
only now, at the output gate, does the accumulated suspicion get squashed and exposed as the hidden state actually used downstream.
what each symbol is ctthe cell state — the conveyor belt's contents, unbounded f, i, oforget, input and output gates — each a number in (0,1) deciding how much passes through c̃the candidate value this step proposes to add ⊙elementwise multiplication — one gate value per dimension of the state

Differentiating ct = f ⊙ ct−1 + i ⊙ c̃ with respect to ct−1 gives the forget gate f, not a weight matrix. A gate near 1 passes a gradient through almost unattenuated — no exponential product of identical matrices, because the update is additive.

LSTM

What: separate cell state and hidden state, three independent gates.

Effect: most expressive gating, most parameters.

Use when: the extra parameters are affordable and you want the store/expose split explicit.

GRU

What: merges cell and hidden state, and merges the forget and input gates into one update gate plus a reset gate.

Effect: roughly 25% fewer parameters, often equal accuracy.

Use when: a smaller model is preferred and the store/expose split is not needed. Which one wins is empirical — there is no theoretical answer, and interviewers who claim otherwise are wrong.

LSTMs pushed usable dependency length from tens of steps to hundreds. The honest limit: this mitigates the 32.3 problem, it does not remove it — gradients still decay, just polynomially rather than exponentially. And it does nothing about a second, separate problem: encoding an entire sequence into one fixed-size vector for another network to consume. That is 32.5.

Interview takeawayThe forget gate turns "multiply by a weight matrix" into "multiply by a number near 1" — the same idea as a residual connection, just inside a recurrent cell.

Seq2seq, and the bottleneck that broke it

WhatAn encoder RNN reads a whole input sequence into one final hidden state; a decoder RNN generates the output from that single vector.
WhyThis was the architecture that made neural machine translation work in 2014 — and the one whose failure mode motivated attention.
Where in MLTranslation, summarisation, and any sequence-to-sequence task before attention.

This section switches domain deliberately: seq2seq and its bottleneck are genuinely a machine-translation story from 2014, and attention's original motivation belongs to that history, not to fraud scoring. Forcing the fraud table into "translate this transaction sequence" would manufacture a coincidence that never happened. 32.6 returns to the fraud table once the mechanism itself — score, softmax, weighted sum — is on the table, because that mechanism does transfer.

Machine translation circa 2014: an encoder RNN reads the source sentence and its final hidden state — one fixed vector, say 512 numbers — is handed to a decoder RNN that generates the translation.

The bottleneck

Every source sentence, whether 5 words or 50, is compressed into the same 512 numbers. The measured consequence was stark: BLEU score was flat for short sentences and fell off a cliff as sentences got longer. The model was not running out of capability; it was running out of vector.

Interview takeawayThe bottleneck is not "RNNs are weak at translation" — it is one specific design choice, squeezing an entire sequence through one fixed-size handoff vector.

Attention as the fix

WhatInstead of one fixed vector, keep every encoder hidden state and let the decoder compute a weighted average over all of them, with weights it decides on the fly.
WhyIt removes the fixed-size bottleneck from 32.5 and, as a side effect, gives every output a direct path back to every input.
Where in MLTranslation originally; now the core operation inside every transformer layer (module 40).

Bahdanau's 2014 idea, stated plainly: stop forcing everything through one vector. Keep every encoder hidden state, and let the decoder, at each output step, compute a weighted average over all of them.

  1. Score the current decoder state against every encoder state: ei = score(s, hi).
  2. Softmax the scores into weights α that sum to 1.
  3. Context vector c = Σ αi hi — a custom summary for this output word.
The analogy

You are no longer allowed only the index card. The whole book stays open on the desk, and for every sentence you write you glance back at the passages that matter for that sentence. The glancing pattern is learned, not fixed.

The mechanism generalises directly to the fraud table from 32.1 — a decoder attending over encoder states maps onto a fraud judgment attending over a customer's own transaction history, which is exactly what module 70 calls a "sequence" feature. Reuse the hidden states already computed in 32.2: h1 = 0.0798, h2 = 0.1095, h3 = 0.9209, h4 = 0.9785. Let the "query" be the final judgment state s = h4, and score it against all four transactions (here just a product, since each h is a single number):

e1 = s·h1 = 0.9785 × 0.0798 = 0.0781  ·  e2 = 0.9785 × 0.1095 = 0.1071
e3 = s·h3 = 0.9785 × 0.9209 = 0.9011  ·  e4 = 0.9785 × 0.9785 = 0.9575
softmax: divide each exp(ei) by their sum (1.0812 + 1.1130 + 2.4623 + 2.6052 = 7.2617)
α = 0.1490.1530.3390.359
c = Σ αihi = 0.149(0.0798) + 0.153(0.1095) + 0.339(0.9209) + 0.359(0.9785) = 0.692
69.8% of the attention weight (0.339 + 0.359) lands on transactions 3 and 4 — the category switch and the large follow-up — with almost nothing on the two ordinary grocery transactions. The weights are inspectable evidence for exactly which rows the judgment leaned on.
what each symbol is eithe raw score between the query and encoder state i αithe softmax-normalised weights — non-negative, sum to 1 cthe context vector — a custom weighted summary of the four transactions

Two properties made this more than a performance patch. It gave a direct path of length 1 between any output and any input — so gradients no longer decay over distance, unlike 32.3's exponential product. And the attention weights were inspectable: plot α as a heatmap (or, here, read the four numbers directly) and a rough alignment emerges without ever having been supervised — though 32.7's last question is a hard caution against over-trusting that inspectability.

Vaswani's 2017 move was the deletion, not the addition. If attention gives every position direct access to every other, the recurrence is doing nothing that attention does not already do — and it is what forces sequential computation. Remove it and the whole sequence can be processed in parallel. That is the sentence the entire transformer follows from, and it is picked up in module 40.

Note the last two rows: the transformer lost two things. Recurrence gave constant-memory inference and position for free. Those losses are exactly what modules 41 (positional encodings) and 45 (KV cache) spend their time managing.

Interview takeawayAttention was a patch for one fixed-size vector; the transformer's actual insight was that the patch made the recurrence redundant, not that attention itself was new in 2017.

Questions

BASICWhy does a plain RNN struggle with long sequences?
Backpropagating through time multiplies by the same weight matrix once per timestep, so the gradient shrinks or grows exponentially with distance. Long-range dependencies get no learning signal.

Concretely: the gradient linking step t to step k contains a product of (t−k) nearly identical Whᵀ diag(tanh′) terms from 32.3. Repeated multiplication by the same quantity is exponential — an effective factor of 0.9 per step leaves you at 0.9⁵⁰ ≈ 0.005 after fifty steps, the same order of magnitude as module 12's fraud base rate. The signal is not weak, it is absent.

Two distinct failure modes with very different remedies: exploding gradients are loud (you see NaNs) and fixed cheaply by clipping the gradient norm. Vanishing gradients are silent — training proceeds, loss goes down, the model simply never learns anything long-range. That silence is why it needed an architectural fix rather than a numerical one.

The connection worth making: this is exactly the vanishing-gradient argument from module 30, but where a deep feed-forward network has different weights per layer, an RNN has the same matrix every step — so the exponential is much cleaner and much worse.

MIDHow does an LSTM fix that, mechanically?
It adds a cell state that is updated by addition and gated multiplication rather than by a fresh matrix multiply each step, giving the gradient a near-multiply-by-1 highway through time.

The update is ct = f ⊙ ct−1 + i ⊙ c̃. Differentiating with respect to ct−1 gives the forget gate f, not a weight matrix. If the model learns f ≈ 1 for a dimension it wants to preserve — such as "this customer probed a new category recently" — the gradient passes through that dimension essentially unattenuated for hundreds of steps.

The three gates divide the labour: forget chooses what to drop, input what to write, output what to expose. The store/expose split matters — the LSTM can carry a fact silently and use it much later, exactly as in the worked 32.4 example where the cell state held suspicion from transaction 3 until it was exposed at transaction 4.

The honest limit: this mitigates, it does not solve. Gradients still decay, just polynomially rather than exponentially, so LSTMs reach hundreds of steps rather than thousands. And nothing here touches the second problem — encoding an entire sequence into one fixed vector. Attention is what solved that.

Worth adding: the same idea appears three times under three names — the LSTM cell state, the residual connection, and the transformer's residual stream. All are "give the gradient a path multiplied by 1." Saying that out loud shows you see the pattern rather than the three diagrams.

MIDWhat problem was attention originally invented to solve?
The fixed-vector bottleneck in seq2seq translation: the encoder crushed a whole source sentence into one vector, and translation quality collapsed as sentences got longer. Attention let the decoder look back at every encoder state instead.

The evidence at the time was unambiguous — BLEU held steady for short sentences and dropped sharply beyond about 30 words. Bahdanau's fix was to keep all encoder states and, at each decoding step, compute a softmax-weighted average of them, with the weights produced by a small learned scoring function.

Two consequences beyond the score. The gradient now has a direct path from any output to any input, so distance stops attenuating learning. And the α weights are interpretable — the published heatmaps showed a soft word alignment emerging with no alignment supervision at all, the same property the 32.6 fraud worked example shows on four transactions instead of words.

The framing that makes this a good answer: attention was a patch bolted onto recurrence. The 2017 insight was subtractive — if attention already connects everything to everything, recurrence contributes nothing except the constraint that forces sequential computation. Delete it and you can process the whole sequence in parallel, which is what made training at today's scale possible. "Attention is all you need" is a claim about what you can remove.

SENIORAre RNNs obsolete?
For general sequence modelling at scale, effectively yes — but the constraint that killed them is coming back as a feature, and the state-space models chasing that are worth knowing about.

Where recurrence still wins: inference memory. A transformer's KV cache grows linearly with context, so a long conversation costs more per token as it goes; an RNN's state is constant-size regardless of history. This is precisely why module 70 frames a sequence model over a customer's history as a second, asynchronous-path model rather than something bolted onto the fast 100ms scoring path — the constant-memory property matters under a latency budget. Attention's O(n²) also stops being free when n is very large.

What is actually happening now: Mamba and the S4/S6 line of state-space models are recurrent at inference — constant state, linear-time scan — but reformulated so training can be parallelised, which is precisely what plain RNNs could not do. RWKV takes a similar route from the other direction. They are competitive at moderate scale; at frontier scale, hybrid designs that keep some attention layers do better than pure ones, apparently because exact recall from context is something attention does and a compressed state does not.

The framing I would give: the field traded constant-memory inference for parallel training, and that trade was overwhelmingly correct while compute for training was the binding constraint. As inference cost becomes the binding constraint — which for a deployed long-context product it now is — the trade is worth re-examining. That is the actual research question, not "are RNNs dead."

SENIORCan you use attention weights to explain what the model is doing?
Only carefully. Attention shows where information was read from, not why the output came out as it did — "attention is not explanation" is a real and well-supported literature.

The arguments against: Jain and Wallace showed you can often find alternative attention distributions that produce the same prediction, so the observed weights are not the unique cause. Attention weights are only the first step of a value-weighted sum inside one head of one layer, and there are dozens of layers of mixing afterwards — a large weight on a transaction whose value vector carries little signal explains nothing. In the 32.6 worked example, the 69.8% weight on transactions 3 and 4 is suggestive, but it is not, by itself, proof that those transactions caused the fraud score rather than merely correlating with the hidden state that produced it.

The counter, from Wiegreffe and Pinter: it depends what you want. Attention is not a faithful explanation, but it is useful evidence, and the adversarial-distribution result does not show the actual learned weights are meaningless.

What I would do instead: for a faithful attribution, use gradient×input, integrated gradients, or an ablation — remove the transaction and measure the effect on the fraud score. Those answer the causal question attention weights only gesture at. For mechanistic work, attention patterns are a hypothesis-generation tool, then activation patching tests the hypothesis.

This connects straight back to module 26: the same discipline applies to SHAP. A method that produces a confident-looking picture is not thereby faithful, and knowing which question a method actually answers is the difference between interpretability and decoration.
