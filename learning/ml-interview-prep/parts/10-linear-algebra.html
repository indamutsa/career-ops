Part A · Maths · Module 10

Linear algebra Machine learning has exactly one data structure — a list of numbers — and exactly one operation — reshaping that list. Linear algebra is the grammar of both. Everything in Parts C and D is this module with more layers.

The problem this was invented to solve

Suppose you want to describe a house. You write down: 120 (square metres), 3 (bedrooms), 1985 (year built), 4.2 (kilometres from the centre). You now have [120, 3, 1985, 4.2]. That list is the house, as far as any model is concerned.

Now suppose you want to describe a word — “king”. There is no obvious list of measurements. But if you invent 300 made-up measurements and let a model choose their values so that similar words end up with similar lists, you get an embedding. Same structure: a list of numbers.

So the two questions linear algebra answers are: how do I compare two lists? and how do I transform a list into a different list? That is the whole subject. Compare = dot product. Transform = matrix multiply.

The one analogy for this module

A vector is a recipe: 2 eggs, 300 g flour, 50 g sugar. A matrix is a machine that converts recipes into other recipes — a machine that turns a cake recipe into a shopping list, say. Matrix multiplication is running the recipe through the machine. And the reason deep learning works at all is that stacking machines end to end, with a small squashing step between them, can express almost any conversion you want.

The terms

Scalar basic a

A single number. A temperature, a loss value, a learning rate.

Your loss at step 4,000 is a scalar. That is why you can plot it as a line.

Vector basic v ∈ ℝⁿ

An ordered list of n numbers. Equivalently: a point in n-dimensional space, or an arrow from the origin to that point.

A recipe. Order matters — swapping the eggs and the flour gives a different dish.

One row of your dataset. One token embedding. One user's feature vector at scoring time.

Dimension basic

How many numbers are in the list. Nothing more mysterious than that.

“d_model = 4096” means every token is described by 4,096 numbers.

Matrix basic A ∈ ℝm×n

A rectangular grid of numbers. Two readings, both useful: a stack of vectors (your whole dataset, one row per example), or a machine that eats an n-vector and returns an m-vector.

A conversion machine with n input dials and m output dials.

Every nn.Linear layer is one matrix plus one bias vector. That is literally all it is.

Tensor basic

The same idea with more axes. Scalar = 0 axes, vector = 1, matrix = 2, and a batch of token embeddings is 3: [batch, sequence, d_model].

Ninety per cent of the shape errors you will ever hit are a disagreement about which axis is which.

Dot product basic a · b

Multiply the two lists element by element, then add it all up. Returns a single number measuring how much the two vectors agree: large and positive if they point the same way, zero if perpendicular, negative if opposed.

Two people rating ten films out of five. Multiply their scores pairwise and sum: a big number means the same taste.

Attention scores are dot products between queries and keys. Retrieval in a vector database is a dot product against every stored document.

Norm basic ‖v‖

The length of a vector. L2 is ordinary straight-line length (√ of the sum of squares). L1 is the sum of absolute values — how far a taxi drives on a grid. L∞ is just the largest single component.

L2 is the crow's flight. L1 is the taxi. L∞ is “what is the worst street”.

Gradient clipping clips the L2 norm. Weight decay penalises squared L2. Lasso penalises L1 and that is precisely why it produces exact zeros.

Cosine similarity basic

The dot product after dividing out both lengths — so it measures direction only, ignoring magnitude. Ranges from −1 to 1.

Two arrows: cosine asks “what angle between them?”, not “which is longer?”.

The default similarity for embeddings, in every vector DB you will ever configure.

Matrix multiplication basic C = AB

Every entry of the result is one dot product: row i of A with column j of B. Shapes must chain: (m×n)(n×p) → (m×p). The inner numbers must match and they vanish.

Running every recipe through every machine and recording all the outcomes.

Over 95 % of the arithmetic in an LLM forward pass is matrix multiplication. GPUs exist because of this one operation.

Transpose basic Aᵀ

Flip the grid over its diagonal: rows become columns.

You will meet it as Q Kᵀ in attention — the transpose is what makes the shapes line up so every query meets every key.

Identity & inverse basic I, A⁻¹

The identity is the do-nothing machine (1s on the diagonal). The inverse is the undo machine: A⁻¹A = I. Many matrices have no inverse — those are called singular.

The closed-form solution to linear regression contains (XᵀX)⁻¹. When two of your features are duplicates, that matrix is singular and the fit blows up — which is exactly what ridge regression fixes by adding λI.

Linear independence & rank mid

A set of vectors is independent if none of them can be built from the others. Rank is how many genuinely independent directions a matrix actually contains — its true information content, which can be far less than its shape suggests.

Ten colleagues on a project, but six of them just repeat what the other four say. The rank of that team is 4.

Rank deficiency is multicollinearity. And “low-rank” is the entire idea behind LoRA: a fine-tuning update turns out to need only a handful of real directions, so you store two skinny matrices instead of one fat one.

Eigenvector & eigenvalue mid Av = λv

A direction that the machine does not rotate — it only stretches or shrinks it. The stretch factor λ is the eigenvalue.

Spin a globe. Almost every point moves. The two poles do not — they are the eigenvectors of that rotation.

PCA is “find the eigenvectors of the covariance matrix, keep the ones with the biggest λ”. Those directions are where your data actually varies.

Determinant mid det(A)

How much the machine scales volume. Zero means it squashes space flat into a lower dimension — information is destroyed and the machine cannot be undone.

det = 0 ⇔ singular ⇔ no inverse ⇔ your linear model has redundant features.

SVD senior A = UΣVᵀ

Every matrix, without exception, is exactly three steps: rotate (Vᵀ), stretch each axis independently (Σ), rotate again (U). The stretch factors are the singular values, sorted biggest first.

Any distortion of an image is: turn it, stretch it along two axes, turn it again.

Keep the top k singular values and you get the best possible rank-k approximation of anything — image compression, PCA, latent semantic analysis, and the justification for LoRA all come out of this one fact.

Orthogonality mid

Two vectors at 90°: their dot product is 0. They carry completely non-overlapping information.

PCA components are orthogonal by construction, which is why they are uncorrelated. Attention heads are not forced to be orthogonal — and in practice many end up redundant, which is what head-pruning research exploits.

The dot product is the whole game

If you take one idea from this module, take this one: the dot product is a similarity score, and almost every important number in modern ML is a dot product.

The attention weight between token 7 and token 3 is a dot product. The logit for the word “Paris” is a dot product between the final hidden state and the “Paris” row of the output embedding. The relevance of a document to your RAG query is a dot product. When you hear “this model has 7 billion parameters”, what you are being told is: there are 7 billion numbers participating in dot products.

Trap

“Cosine similarity and Euclidean distance rank things the same way.” Only if all your vectors are already normalised to unit length — then they are monotonically related and the ranking is identical. Unnormalised, they disagree, and they disagree in a way that matters: raw dot product rewards long vectors, so a document that simply repeats a word many times can beat a genuinely relevant short one. Most embedding models normalise their output for exactly this reason.

A matrix is a machine, and eigenvectors are its grain

Feed every point of a square through a 2×2 matrix and the square becomes a parallelogram. The matrix has stretched, squashed, sheared and rotated space. The eigenvectors are the special directions that came out pointing the same way they went in — the grain of the wood. The eigenvalues say by how much each of those directions was stretched.

Why anyone cares: if you want to know what a transformation does, you do not read its sixteen numbers. You read its eigenvalues. An eigenvalue bigger than 1 means that direction is amplified; applied repeatedly, it explodes. Smaller than 1 means it decays to nothing. This is not an analogy for exploding and vanishing gradients — it is exploding and vanishing gradients. An RNN applies roughly the same matrix at every timestep, so after 100 steps the signal has been multiplied by λ¹⁰⁰, and unless λ sits very close to 1 the result is either astronomical or zero.

Why L1 makes zeros and L2 does not

This is the most-asked linear-algebra question in an ML interview that is not really about linear algebra, and the answer is entirely geometric.

Penalising a norm means: find the lowest loss you can, while staying inside a ball of some fixed size. The L2 ball is a circle. The L1 ball is a diamond, with its corners sitting exactly on the axes.

Your loss contours are ellipses sliding outward from the unconstrained optimum. The solution is where a contour first touches the ball. A circle has no corners, so the touch point can be anywhere — and “anywhere” almost never has a coordinate of exactly zero. A diamond has sharp corners pointing along the axes, and a smooth curve touching a sharp corner is overwhelmingly the likely outcome. At a corner, one coordinate is exactly zero.

Say it in one line

“L1 gives sparsity because its constraint region has corners on the axes, and contours tend to hit corners. L2's region is round, so nothing is ever driven exactly to zero — only shrunk.”

Questions

BASICExplain the dot product to someone with no maths background.
It is a single number that says how much two lists of numbers agree — big and positive when they point the same way, zero when they are unrelated, negative when they oppose.

Mechanically: multiply the two lists entry by entry and add up the results. Geometrically it equals ‖a‖‖b‖cos θ, so it factors into “how long are they” times “how aligned are they”.

The everyday version I use: two people each rate ten films out of five. Multiply their scores pairwise and sum. Similar taste gives a big number. That number is the dot product.

Where it shows up: an attention score is a dot product between a query and a key; a vector database retrieves by dot product; the logit for a token is a dot product with an output embedding row.

Trap

“So a bigger dot product always means more similar?” No — it also grows with length. A vector that is simply large scores highly against everything. That is why we normalise and use cosine.

BASICWhat do the shapes have to satisfy to multiply two matrices, and why?
(m×n)(n×p) → (m×p): the inner dimensions must match, and they disappear.

Because every output entry is a dot product between a row of the first and a column of the second, and a dot product needs both lists to be the same length. That shared length is the inner dimension, and it is consumed by the summation.

In practice this is the mental check I run on every layer: a Linear(768, 3072) holds a (3072×768) matrix, so [batch, seq, 768] → [batch, seq, 3072]. The last axis is the only one the matrix touches.

Trap

Matrix multiplication is not commutative. AB ≠ BA — often the shapes do not even permit BA. It is associative, which is why (QKᵀ)V and Q(KᵀV) give the same answer but wildly different cost — the second is the trick behind linear-attention variants.

MIDWhy do embedding systems use cosine similarity rather than Euclidean distance?
Because in an embedding space direction carries the meaning and magnitude mostly carries frequency artefacts, and cosine throws magnitude away.

Embedding vectors get their length from things you usually do not want to rank on — how common a token is, how long the document was, how many times a word was repeated. Two texts about the same topic at very different lengths land in the same direction but at different distances from the origin. Euclidean distance would call them dissimilar; cosine calls them identical, which is what you meant.

The practical note: once vectors are L2-normalised, cosine similarity and dot product are the same operation, and Euclidean distance becomes a monotone function of it — so the ranking is identical and you may as well use the dot product, because it is a single fused GPU kernel. That is why FAISS indexes are usually built on inner product over normalised vectors.

Trap

Cosine is not always right. If magnitude genuinely means something — a count vector where “bought 50 items” should differ from “bought 1 item” — throwing it away destroys the signal. Ask what the magnitude encodes before you normalise it.

MIDWhat is the rank of a matrix, and when has it ever mattered to you?
Rank is the number of genuinely independent directions in a matrix — its real information content, as opposed to its shape.

A 1000×1000 matrix whose every column is a multiple of the first has rank 1. Its shape claims a million numbers; it contains about a thousand.

Three places it bites in practice:

  • Multicollinearity. Two features that are near-duplicates make XᵀX near-singular, so (XᵀX)⁻¹ becomes enormous and unstable — coefficients swing wildly and flip sign between refits. Ridge fixes it by adding λI, which lifts every eigenvalue away from zero.
  • Dimensionality reduction. PCA is the statement that your data's covariance matrix is effectively low rank, so you can drop directions with tiny eigenvalues and lose almost nothing.
  • LoRA. The empirical claim is that the update a fine-tune needs is intrinsically low rank. So instead of learning a full d×d matrix you learn B·A with inner dimension r ≈ 8–64. You train under 1 % of the parameters and can hot-swap adapters at serving time.
Trap

“Is LoRA lossless?” No. It constrains the update to a rank-r subspace. For instruction tuning that is usually enough, because the update genuinely is low rank. For teaching the model a new domain — new vocabulary, new language — it is often not, and full fine-tuning wins.

MIDExplain eigenvectors to a product manager.
They are the directions a transformation leaves pointing the same way — it can stretch them, but it cannot turn them.

Spin a globe: every city moves except the two poles. The poles are the eigenvectors of that rotation, with eigenvalue 1 because they are not even stretched.

Why they earn their keep: if you want to know what a complicated transformation actually does, you do not read its entries — you read its eigenvalues. Bigger than 1 means that direction gets amplified every time you apply the matrix; less than 1 means it dies away. That single fact explains exploding and vanishing gradients in an RNN, where roughly the same matrix is applied at every one of a hundred timesteps.

And PCA is nothing but: take the covariance matrix of your data, find its eigenvectors, keep the ones with the largest eigenvalues. Those are the directions along which your data actually varies.

Trap

Not every matrix has a full set of real eigenvectors — a 2-D rotation has none, since every direction turns. Symmetric matrices always do, with real eigenvalues and orthogonal eigenvectors, which is precisely why PCA is well behaved: covariance matrices are symmetric.

SENIORHow are PCA and SVD related?
PCA is SVD applied to mean-centred data — the principal components are the right singular vectors, and the variance explained is the squared singular values.

The textbook route to PCA is: build the covariance matrix C = XᵀX/(n−1) and eigendecompose it. The route everyone actually uses is: take the SVD of the centred X directly, X = UΣVᵀ. Then the columns of V are the principal directions and σᵢ²/(n−1) is the variance along component i.

You prefer the SVD route for a numerical reason, and it is worth saying out loud: forming XᵀX squares the condition number. Small singular values become vanishingly small eigenvalues and get lost in floating-point noise. SVD works on X directly and never forms that product, so it stays stable on ill-conditioned data.

The deeper statement is the Eckart–Young theorem: truncating the SVD to the top k singular values gives the provably best rank-k approximation of the matrix in both Frobenius and spectral norm. That single theorem underwrites PCA, image compression, latent semantic analysis, and the intuition behind low-rank adapters.

Trap

PCA requires centring, and it is scale-sensitive. Forget to standardise and a feature measured in metres will dominate one measured in kilometres purely because of units. Also: PCA finds directions of maximum variance, which is not the same as directions useful for your label. It is unsupervised, and it will happily discard the low-variance direction that was the only one carrying signal.

SENIORWhy does the L1 penalty produce exact zeros when L2 does not?
Because the L1 constraint region is a diamond with corners on the axes, and loss contours expanding outward overwhelmingly first touch a corner — where a coordinate is exactly zero.

Set it up as constrained optimisation: minimise the loss subject to ‖w‖ ≤ t. The solution is the point where an expanding loss contour first touches the feasible region. L2's region is a ball — smooth everywhere, so the touch point is generically in the interior of a face and every coordinate is nonzero but shrunk. L1's region is a cross-polytope whose vertices lie on the axes, and a smooth convex contour meeting a polytope generically meets it at a vertex.

The calculus version, if they push: the L2 gradient is 2w, which goes to zero as w does — the push toward zero fades exactly when you get there, so you approach but never arrive. The L1 subgradient is sign(w), constant magnitude 1 all the way in. There is a finite push right up to the origin, so the coefficient is driven to exactly zero and pinned there.

Trap

“So always use lasso for feature selection?” Careful. With correlated predictors lasso picks one of the group essentially arbitrarily and zeroes the rest — refit on a bootstrap sample and you may get a different chosen feature. If you need stable selection use elastic net, which adds an L2 term to keep correlated features in or out together.

SENIORWhy is matrix multiplication the thing GPUs are built for, and where does that bite in LLM serving?
Because a matmul is O(n³) arithmetic over O(n²) data — a huge amount of compute per byte loaded — so it is the rare operation that can actually saturate a modern accelerator.

Multiplying two n×n matrices is n³ multiply-adds while touching only 3n² numbers. That arithmetic intensity of roughly O(n) is what lets a GPU stay busy instead of waiting on memory. Nearly everything else in a network — activations, normalisation, elementwise adds — has intensity around 1 and is purely memory-bandwidth-bound, which is why kernel fusion pays for itself.

Where it bites in serving is the split between the two phases:

  • Prefill processes the whole prompt at once. Big matrix times big matrix, compute-bound, near peak FLOPs.
  • Decode generates one token at a time. Now it is a matrix times a vector: n² arithmetic over n² data, intensity ≈ 1. You are reading the entire model from HBM to produce a single token, so you are bandwidth-bound and the GPU is mostly idle.

Everything in inference optimisation follows from that asymmetry. Continuous batching exists to turn many decode vectors back into a matrix so the weight read is amortised. Quantisation helps decode far more than prefill, because it shrinks the bytes you must move. Speculative decoding works because verifying k drafted tokens costs one weight read instead of k.

Trap

“So just make the batch enormous.” The KV cache grows linearly with batch × sequence length, and at long contexts it can exceed the size of the weights. You run out of memory before you run out of compute — which is why paged attention and GQA exist.
