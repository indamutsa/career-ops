One of the two modules you may legitimately skim if time is short (the other is 33). Read 31.1–31.4 and the questions on equivariance and CNN-vs-ViT; the architecture timeline is recognition-level knowledge.

Why a dense layer is the wrong tool for an image

Take a modest 224×224 colour image. Flattened, that is 150,528 numbers. A single dense hidden layer of 1,000 units needs 150 million weights — for one layer — and it would treat the pixel at (0,0) and the pixel at (0,1) as entirely unrelated inputs, learning their relationship from scratch if at all.

Convolution encodes two assumptions that fix both problems at once:

  • Locality. A meaningful feature — an edge, a corner — is made of pixels that are near each other. So a unit only needs to look at a small window.
  • Translation equivariance via parameter sharing. An edge detector that works in the top-left works in the bottom-right, so use the same weights everywhere. One 3×3 filter is 9 weights regardless of image size.

That is the inductive bias from module 20, stated concretely: the architecture asserts something true about images before any data arrives, and gets enormous sample efficiency in return.

The convolution, seen

The terms

Kernel / filter basic

The small grid of learned weights — usually 3×3 — that slides across the input.

A rubber stamp you press at every position, recording how well the pattern under it matches the pattern on the stamp.

Feature map basic

The output of one filter across the whole input: a map of where that filter's pattern occurs.

A layer with 64 filters produces 64 feature maps — 64 channels for the next layer.

Channels basic

The depth of a tensor. 3 at the input for RGB; hundreds in the middle of a network.

A kernel spans all input channels. A "3×3" filter over 64 input channels really has 3×3×64 = 576 weights.

Stride basic

How far the window moves per step. Stride 2 halves the output's spatial size.

The modern alternative to pooling for downsampling — a strided convolution learns how to reduce rather than applying a fixed rule.

Padding basic

valid = no padding, output shrinks. same = pad with zeros so the output keeps the input's size.

Without padding, a 3×3 conv shrinks each side by 2 per layer, so a deep stack would run out of image. It also under-uses the border pixels.

Pooling basic

Downsample by taking the max (or mean) of each small region.

Squinting. Detail disappears, the overall arrangement survives.

Max pooling adds a little translation invariance: shift the input by one pixel and the max over a 2×2 window frequently does not change.

Receptive field mid

The region of the original input that influences one particular unit deep in the network.

It grows with depth: two stacked 3×3 layers see 5×5, three see 7×7. A unit cannot use information outside its receptive field, so a network that must reason about the whole image needs enough depth (or dilation, or global pooling) to see it.

Equivariance vs invariance senior

Equivariant: move the input, the output moves the same way. Invariant: move the input, the output does not change.

Convolution is equivariant. Pooling and global average pooling convert that gradually into invariance. Getting this distinction right is a common senior-level check.

1×1 convolution senior

A convolution with no spatial extent. It mixes channels at each position and nothing else.

The cheap way to change channel count — the bottleneck in ResNet and Inception. It is exactly a per-position dense layer, which is also what a transformer's FFN is.

Depthwise separable conv senior

Split a convolution into a spatial pass per channel, then a 1×1 pass to mix channels.

Roughly 8–9× fewer operations than a full 3×3 conv for similar accuracy. The core of MobileNet, and the reason on-device vision works at all.

Dilated / atrous conv mid

A kernel with gaps, so it covers a wider area with the same number of weights.

Grows the receptive field without losing resolution — used in segmentation and in WaveNet-style audio models.

Global average pooling mid

Average each feature map down to a single number, giving one vector per image.

Replaced the enormous dense layers at the end of AlexNet/VGG. Far fewer parameters, and it makes the network accept any input size.

The architecture timeline — what each one contributed

ModelYearThe idea it added
LeNet-51998The template: conv, pool, conv, pool, dense. Read cheques for a decade
AlexNet2012The moment the field turned. ReLU instead of tanh, dropout, aggressive augmentation, and two GPUs. Halved the ImageNet error rate
VGG2014Depth via uniform 3×3 stacks — established that small kernels stacked deep beat large kernels
Inception / GoogLeNet2014Multiple kernel sizes in parallel, plus the 1×1 bottleneck to keep it affordable
ResNet2015Residual connections. Made 150+ layers trainable and became the default backbone for years — module 30.6

Questions

BASICWhat does a convolutional layer do that a dense layer does not?
It looks at small local windows and reuses the same weights at every position. That gives it a fraction of the parameters and a built-in assumption that a pattern means the same thing wherever it appears.

The arithmetic makes it vivid. A dense layer connecting a 224×224×3 image to 1,000 units needs about 150 million weights. A 3×3 convolution with 64 filters over 3 input channels needs 3×3×3×64 = 1,728 — five orders of magnitude fewer, and it works on any input size.

The two assumptions that buy that: locality, since an edge is made of adjacent pixels, so a unit does not need to see the whole image; and parameter sharing, since a vertical-edge detector is useful everywhere, so the same nine weights apply at every position.

And the consequence worth stating: with far fewer parameters and a correct prior, a CNN generalises from far less data than a dense network could. That is the inductive-bias argument in its most concrete form.

MIDHow many parameters are in a 3×3 conv layer with 64 input and 128 output channels?
3 × 3 × 64 × 128 + 128 = 73,856 — kernel area times input channels times output channels, plus one bias per output channel.

The step people miss is that each filter spans all input channels. A "3×3 filter" here is really a 3×3×64 volume, so it has 576 weights; there are 128 such filters; plus 128 biases.

Two things worth adding, because they are what the question is really probing:

  • Parameter count is independent of input resolution. The same layer applies to a 32×32 or a 512×512 image. What changes with resolution is the compute and the activation memory, not the parameters — and activation memory is usually what actually limits your batch size.
  • FLOPs are a different question. Roughly output positions × 3 × 3 × 64 × 128 multiply-adds. At 56×56 output that is around 231 million MACs for this one layer. Parameters and compute must be reasoned about separately, which is exactly the point behind depthwise separable convolutions.
MIDWhy stack two 3×3 convolutions instead of using one 5×5?
Same receptive field, fewer parameters, and an extra non-linearity in between.

Two stacked 3×3 layers see a 5×5 region of the input, so their receptive field matches. But per channel pair, two 3×3s cost 18 weights against a 5×5's 25 — about 28 % fewer — and the gap widens for 7×7, where three stacked 3×3s cost 27 against 49.

The more interesting benefit is the non-linearity between them. A 5×5 layer is one linear operation followed by one activation. Two 3×3 layers give two activations, so the composite function is strictly more expressive over the same spatial extent. That was VGG's core finding and it is why 3×3 became the universal default.

The boundary I would add: this is not unconditional. Very large kernels came back in ConvNeXt and RepLKNet, where 7×7 depthwise convolutions work well — because a depthwise kernel's cost grows much more slowly with area, so the parameter argument that killed large kernels no longer applies. The rule was a consequence of the cost model, and the cost model changed.

SENIORIs a CNN translation invariant?
No — convolution is equivariant, not invariant. Shift the input and the feature map shifts identically. Invariance is approximated later, by pooling and by global average pooling.

The distinction matters and it is a common trap: equivariant means f(shift(x)) = shift(f(x)) — the information moves with the input. Invariant means f(shift(x)) = f(x) — the output does not care where the thing is. A classifier wants invariance; a segmentation model wants equivariance, since it must report where.

How invariance actually gets built: max pooling gives a little, since the max over a 2×2 window often survives a one-pixel shift. Stacking many of those accumulates more. Global average pooling at the head gives full invariance to translation by collapsing all spatial positions. So a classification CNN is equivariant in its body and invariant at its head, by construction.

The important caveat, from Azulay and Weiss and from Zhang's work on anti-aliasing: modern CNNs are much less shift-invariant than people assume. Strided convolutions and pooling violate the Nyquist criterion, so shifting an image by one pixel can change the prediction substantially. Blurring before downsampling — anti-aliased pooling — measurably improves it. That is a good detail to have: the textbook property is approximate, and in a way that has been measured and partly fixed.

And the honest note about the rest: CNNs are not invariant to rotation or scale at all. Those come from data augmentation, not architecture, which is why augmentation is doing more work than it is usually credited with.

MIDWhat is a 1×1 convolution for?
It mixes channels at each spatial position without touching the neighbourhood — a cheap way to change channel count, and exactly a per-position dense layer.

Three jobs it does:

  • Dimensionality reduction. The bottleneck pattern in ResNet: 1×1 down to 64 channels, do the expensive 3×3 there, 1×1 back up to 256. The 3×3 then operates on a quarter of the channels, which is where most of the saving comes from.
  • Channel mixing. A depthwise convolution processes each channel separately and never combines them; the 1×1 that follows is what does the combining. That two-step split is the whole of depthwise separable convolution.
  • Adding non-linearity cheaply. Each 1×1 comes with an activation, so it increases depth and expressiveness for very little compute.

The connection worth drawing: a 1×1 convolution over C channels is a dense layer applied independently at every position with shared weights. Which means a transformer's position-wise FFN is the same operation on a sequence instead of a grid. Noticing that unification is the kind of thing that reads as real understanding rather than memorisation.

SENIORVision transformers beat CNNs. Does that mean convolution was a mistake?
No — it means a strong inductive bias is worth a lot when data is scarce and becomes a constraint when data is abundant. ViTs beat CNNs above a data threshold and lose below it, which is exactly what that trade predicts.

The empirical shape, from the original ViT paper: trained on ImageNet-1k alone, ViT underperforms a comparable ResNet. Pretrained on ImageNet-21k it draws level. On JFT-300M it wins clearly. The architecture did not change; the data did.

Why: a CNN has locality and translation equivariance hard-coded. Those are true facts about images, given for free, and they save an enormous amount of data. A ViT assumes almost nothing — self-attention lets any patch attend to any other from layer 1 — so it must learn that locality matters. With enough data it learns something better than the hand-coded prior, including long-range relationships a CNN can only reach after many layers of receptive-field growth. With too little data it never gets there.

The complication that makes this a good answer rather than a neat one: ConvNeXt took a plain ResNet and applied the training recipe that came with transformers — AdamW, heavy augmentation, long schedules, LayerNorm, larger depthwise kernels — and matched ViT performance. So a substantial part of the apparent architectural gap was actually a training-recipe gap. The honest summary is that at scale, architecture matters less than data, compute and recipe — and that hybrid designs like Swin, which reintroduce locality into attention, are what most production vision systems actually use.

What I would take from it for an LLM role: the same argument runs in reverse for language. Transformers won there earlier and more decisively because text data was already abundant and because the useful dependencies genuinely are long-range, so a locality prior would have been a false assumption rather than a helpful one.
