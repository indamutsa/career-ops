Convolutional networks The architecture that started the deep-learning era. For an LLM-focused role this is background rather than the main event — but the ideas in it (parameter sharing, inductive bias, receptive fields, the 1×1 bottleneck) recur constantly, and "why did transformers beat CNNs" is a question you should be able to answer properly. The running example is a scanned ID photo going through account-opening verification — the same kind of image a CNN forgery detector scores in a real KYC (know-your-customer) pipeline.

How to read this module

One of the two modules you may legitimately skim if time is short (the other is 33). Read through the convolution and channel arithmetic and the questions on equivariance and CNN-vs-ViT; the architecture timeline is recognition-level knowledge.

Why a dense layer is the wrong tool for a document image

A bank opening a new account asks a scanned ID photo one question: is this a genuine capture of a real ID, or has it been photographed off a screen, printed and rescanned, or edited to swap in a different face or a different birth date? That question is answered by looking for small, local give-aways — a moiré pattern, a pasted-photo seam, a mismatched font — wherever they happen to sit in the image. A dense (fully-connected) layer is the wrong tool for that job.

WhatA convolutional layer slides a small set of learned weights across an image, producing one output value per position, instead of connecting every input pixel to every output unit.
WhyA dense layer on a modest image needs hundreds of millions of weights for one layer, and it treats the pixel at (0,0) and the pixel at (0,1) as unrelated inputs it must learn to relate from scratch.
Where in MLAny input with spatial structure — photos, scanned ID or check images, spectrograms — where a local pattern (an edge, a seam, a signature stroke) means the same thing wherever it appears.
image = 224 × 224 × 3 (a modest colour scan of the ID, 3 channels for red/green/blue)
flattened length = 224 × 224 × 3 = 150,528 numbers
dense layer to 1,000 hidden units: weights = 150,528 × 1,000 = 150,528,000 ≈ 150 million
150 million weights for one layer, on one modest image — and the layer still has no notion that two neighbouring pixels are related. It would have to learn "these two pixels sit next to each other" independently for every one of the 150,528 input positions.

Convolution encodes two assumptions that fix both problems at once:

  • Locality. A meaningful feature — a pasted-photo seam, a font mismatch — is made of pixels that are near each other. So a unit only needs to look at a small window.
  • Translation equivariance via parameter sharing. A seam detector that works in the top-left works in the bottom-right, so use the same weights everywhere. One 3×3 filter is 9 weights regardless of image size.
images have local structure → assume locality + share weights across positions → orders of magnitude fewer weights than a dense layer → an inductive bias (module 20): the architecture asserts something true about images before any data arrives, and gets sample efficiency in return.
Interview takeawayState the two assumptions by name — locality and parameter sharing — and be ready to show the parameter-count arithmetic that follows from them.

The convolution operation, computed by hand

WhatMultiply a small grid of learned weights (the kernel) against a matching patch of the input, sum the products into one number, then slide the kernel to the next position and repeat.
WhyThis is the concrete arithmetic behind locality and parameter sharing — one small set of weights, reused at every position, produces a whole map of where its pattern occurs.
Where in MLEvery convolutional layer, from the first layer that sees raw pixels to the last one before the classification head.
?The vocabulary: kernel, feature map, stride, padding

Kernel / filter: the small grid of learned weights — usually 3×3 — that slides across the input. A rubber stamp pressed at every position, recording how well the pattern under it matches the pattern on the stamp.

Feature map: the output of one filter across the whole input — a map of where that filter's pattern occurs. A layer with 64 filters produces 64 feature maps.

Stride: how far the window moves per step. Stride 1 moves one pixel at a time; stride 2 moves two, which roughly halves the output's spatial size.

Padding: valid means no padding, so the output shrinks a little at every layer; same means pad the border with zeros so the output keeps the input's size. Without padding, a deep stack of 3×3 layers would eventually run out of image.

patch P (grayscale brightness, 0–255, from a corner of the ID photo where a replacement photo may have been pasted over the original): 1012200815205119198 kernel K (a vertical-edge detector — negative on the left, positive on the right): −101−101−101
row 1: 10(−1) + 12(0) + 200(1) = −10 + 0 + 200 = 190
row 2: 8(−1) + 15(0) + 205(1) = −8 + 0 + 205 = 197
row 3: 11(−1) + 9(0) + 198(1) = −11 + 0 + 198 = 187
output at this position = 190 + 197 + 187 = 574
Nine multiplications and one sum — exactly the multiply-then-add pattern of the dot product from module 10.3, just applied to a 3×3 patch instead of a 4-number house vector. A large positive output means the left side of the patch is dark and the right side is bright: a sharp intensity jump, which is what a pasted-photo edge looks like. Slide this same 9-weight kernel to every position in the image and the collection of outputs is the feature map.
what each symbol is Pthe image patch under the kernel right now — nine pixel brightness values Kthe kernel — nine learned weights, the same nine at every position in the image 574the feature-map value at this one position — how strongly this patch matches "dark-to-light edge"
Interview takeawayConvolution is the dot product from module 10, applied to a small local patch instead of a whole vector, with the same nine weights reused at every position.

Channels, and what a "3×3 filter" really costs

WhatChannels are the depth of a tensor — 3 at the input for RGB, hundreds in the middle of a network — and a kernel spans all of the input channels, not just one.
WhyThe true weight count of a convolutional layer depends on the channel depth, not just the kernel's spatial size, and this is a standard place interviewers probe.
Where in MLSizing a model, estimating memory and compute, and comparing architectures.
rule: weights per layer = k × k × Cin × Cout (kernel area × input channels × output filters), plus one bias per output filter
substitute: k = 3 (3×3 kernel), Cin = 3 (the ID photo's red/green/blue channels), Cout = 64 (64 filters in this layer)
3 × 3 × 3 × 64 = 1,728 weights, plus 64 biases = 1,792 parameters total
A "3×3 filter" over 3 input channels is really a 3×3×3 volume — 27 weights, not 9 — and there are 64 such filters. Against the dense layer's 150 million from 31.1, this is five orders of magnitude fewer, and it works on any input resolution: a 224×224 scan and a 512×512 scan use the exact same 1,792 numbers.
what each symbol is kthe kernel's spatial size — 3, for a 3×3 kernel Cininput channels — 3 for the RGB scan at this first layer Coutoutput filters — 64, chosen when the layer is designed
Interview takeawayMultiply in the channel dimension: a kernel's real weight count is k × k × Cin × Cout, and it does not grow with image resolution.

Downsampling: stride, padding and pooling

WhatPooling downsamples a feature map by taking the max (or mean) of each small region, shrinking its spatial size without adding any learned weights.
WhyA network needs to reduce spatial resolution as it goes deeper, both to cut compute and to start discarding exact position in favour of "is this pattern present at all".
Where in MLClassic CNNs (LeNet, AlexNet, VGG) between convolutional blocks; modern networks often use a strided convolution instead, so the reduction itself is learned rather than fixed.
bottom-right 2×2 block of the patch from 31.2: 152059198
max(15, 205, 9, 198) = 205
now shift the whole block one pixel to the right, so the block becomes 205206198199 — still centred on the same bright region
max(205, 206, 198, 199) = 206 — nearly unchanged
The exact pixel that produced the maximum moved, but the reported value barely did: a one-pixel shift in where the bright region sits made almost no difference to the pooled output. That is the beginning of translation invariance — squinting at the feature map so detail disappears and the overall "is something bright here" survives. Section 31.6 makes the invariance-vs-equivariance distinction precise.
Interview takeawayStride and pooling both downsample; a strided convolution learns how to reduce, while pooling applies a fixed rule and adds a little translation invariance for free.

Receptive field — how far one unit can see

WhatThe receptive field of a unit is the region of the original input that can influence its value.
WhyA unit cannot use information outside its receptive field, so a network that must reason about a whole ID photo — not just one 3×3 corner — needs enough depth (or dilation, or global pooling) to see all of it.
Where in MLChoosing network depth, kernel size, and dilation rate for a task that needs long-range context, such as checking whether a signature on page one matches a name printed on page two.
?Deriving the receptive-field growth
rule (stride 1 throughout): RFL = RFL−1 + (k − 1)
layer 1, a single 3×3 kernel: RF1 = 3
layer 2: RF2 = 3 + (3 − 1) = 5
layer 3: RF3 = 5 + (3 − 1) = 7
Two stacked 3×3 layers see a 5×5 region of the original image; three see 7×7. Each additional 3×3 layer adds 2 pixels of receptive field on every side. To let one unit see a 51×51 region — large enough to compare a photo corner against a signature elsewhere on the same ID — a stack of plain 3×3 layers needs roughly 25 layers, which is exactly the pressure that motivates dilation (31.9) and the very deep residual stacks of module 30.6.
Interview takeawayReceptive field grows with depth, roughly 2 pixels per side per stacked 3×3 layer; state the arithmetic, don't just gesture at "it gets bigger".

Equivariance vs invariance

WhatEquivariant: move the input, the output moves the same way — f(shift(x)) = shift(f(x)). Invariant: move the input, the output does not change — f(shift(x)) = f(x).
WhyA classifier deciding "genuine or forged" wants invariance — it should not matter where on the photo the tamper seam sits. A model reporting where the seam is (for a reviewer to look at) wants equivariance.
Where in MLImage classification heads (invariance), segmentation and object detection (equivariance).
Back to the tamper seam

If a forger shifts the pasted-in photo a few pixels to hide the seam near the edge instead of the centre, the convolution in 31.2 still fires — its output feature map shows the same 574-style edge response, just relocated by the same few pixels. That is equivariance: the detection moved with the tamper. But the account-opening decision only needs "is there a seam somewhere on this ID", not "exactly which pixel". Pooling (31.4), stacked repeatedly, and then a global average pooling layer (31.9) at the very end collapse that shifted response down to one yes/no signal that no longer depends on position. That is where invariance comes from — it is built, not automatic.

Trap

"CNNs are translation invariant" is the wrong claim. Convolution itself is equivariant. Invariance is approximated afterward, by pooling and especially by global average pooling at the head — a classification CNN is equivariant in its body and invariant at its head, by construction, and only approximately even then.

Interview takeawayConvolution is equivariant, not invariant; invariance is built afterward by pooling. Getting this distinction right is a common senior-level check.

The 1×1 convolution

WhatA convolution with no spatial extent — a 1×1 kernel. It mixes channels at each position and touches no neighbouring pixels.
WhyIt is the cheap way to change channel count, and it is exactly a per-position dense layer.
Where in MLThe bottleneck in ResNet and Inception; the channel-mixing step in depthwise separable convolutions (31.8).
at one pixel position, the Cin-channel vector there → multiply by a Cin × Cout weight matrix → a Cout-channel vector at that same position. That is exactly module 10.6's p = Xw matrix multiply — X the channel vector, w the 1×1 kernel's weights — run once per pixel instead of once per house.
Interview takeawayA 1×1 convolution over C channels is a dense layer applied independently at every position with shared weights — the same operation as module 10's matrix multiply, just per-pixel instead of per-row. (Module 32's transformer feed-forward network — a small dense layer applied independently at each token position — is the identical idea on a sequence instead of a grid; worth noting now, even before module 32 defines it in full.)

Depthwise separable convolutions

WhatSplit an ordinary convolution into two cheaper passes: a spatial convolution applied to each channel separately (depthwise), then a 1×1 convolution to mix channels (pointwise).
WhyA full 3×3 convolution mixes space and channels in one expensive step; splitting the two jobs apart removes most of the redundant computation for similar accuracy.
Where in MLMobileNet and on-device vision generally, where compute and battery are the binding constraint.
?Deriving the ~8× saving
same layer as 31.3's larger example: k = 3, Cin = 64, Cout = 128
standard 3×3 convolution: k × k × Cin × Cout = 3 × 3 × 64 × 128 = 73,728 weights
depthwise pass (one 3×3 kernel per input channel, no mixing): k × k × Cin = 3 × 3 × 64 = 576 weights
pointwise pass (a 1×1 convolution mixing the 64 channels into 128): Cin × Cout = 64 × 128 = 8,192 weights
depthwise separable total: 576 + 8,192 = 8,768 weights
ratio: 73,728 / 8,768 ≈ 8.4× fewer weights (and roughly the same ratio in multiply-adds)
The depthwise pass is nearly free (576 weights) because it never mixes channels; almost the entire cost of the separable version is the 1×1 pointwise pass. That matches the commonly quoted "roughly 8–9× fewer operations" and is the core trick behind MobileNet.
Interview takeawayDepthwise separable = a depthwise spatial pass (cheap) plus a 1×1 pointwise pass (does the mixing, and most of the cost) — roughly 8–9× fewer operations than one full 3×3 convolution over the same channels.

Two more building blocks: dilation and global average pooling

WhatA dilated (atrous) convolution spreads a kernel's weights apart with gaps between them, so it covers a wider area without adding weights. Global average pooling (GAP) averages an entire feature map down to a single number.
WhyDilation grows the receptive field from 31.5 without the depth (and resolution loss) that stacking more layers would cost. GAP replaces the huge dense layers that used to sit at the end of a CNN, and is what finally makes the head fully translation-invariant (31.6).
Where in MLDilation: segmentation, WaveNet-style audio models. GAP: the classification head of nearly every modern CNN.
effective size = k + (k − 1)(r − 1), where r is the dilation rate
k = 3, r = 2 (one gap inserted between each weight): 3 + (3 − 1)(2 − 1) = 5
Still only 9 learned weights, but they now sample a 5×5 area of the input instead of a solid 3×3 — the same jump the two-stacked-layers arithmetic in 31.5 needed two layers to reach, done in one.

Global average pooling does the arithmetic you would expect: take one feature map (say, the 64th filter's output across the whole ID photo) and report the single number that is the mean of every value in it. One feature map in, one number out; 64 feature maps in, a 64-number vector out — far fewer parameters than a dense layer over every pixel, and the network now accepts any input size, since averaging works the same way regardless of how many pixels are being averaged.

Interview takeawayDilation buys receptive field without extra depth or extra weights; global average pooling replaces the classic end-of-network dense layers and supplies most of a CNN's translation invariance.

The architecture timeline — what each one contributed

ModelYearThe idea it added
LeNet-51998The template: conv, pool, conv, pool, dense. Read cheques for a decade
AlexNet2012The moment the field turned. ReLU instead of tanh, dropout, aggressive augmentation, and two GPUs. Halved the ImageNet error rate
VGG2014Depth via uniform 3×3 stacks — established that small kernels stacked deep beat large kernels
Inception / GoogLeNet2014Multiple kernel sizes in parallel, plus the 1×1 bottleneck to keep it affordable
ResNet2015Residual connections. Made 150+ layers trainable and became the default backbone for years — module 30.6
DenseNet2016Every layer connected to every later layer; strong feature reuse
MobileNet2017Depthwise separable convolutions; CNNs on phones
EfficientNet2019Compound scaling — depth, width and resolution scaled together by a fixed rule rather than one at a time
Vision Transformer2020Drop convolution entirely: cut the image into patches and run a transformer. Beats CNNs given enough data
ConvNeXt2022A CNN modernised with transformer-era training recipes, matching ViT — evidence that much of the gap was the recipe, not the architecture
Back to the account-opening pipeline

Any of the backbones above can end in a single sigmoid output: a forgery score for the scanned ID photo. That score is one more signal into the same fraud pipeline from module 12 — where the base rate of fraud among applications was P(fraud) = 0.005 — feeding the action bands from module 12.1: block above 0.9, review between 0.3 and 0.9, allow below 0.3. The CNN does not replace that pipeline; it supplies one more number for it to threshold.

Questions

BASICWhat does a convolutional layer do that a dense layer does not?
It looks at small local windows and reuses the same weights at every position. That gives it a fraction of the parameters and a built-in assumption that a pattern means the same thing wherever it appears.

The arithmetic makes it vivid, and it is the same arithmetic from 31.1 and 31.3. A dense layer connecting a 224×224×3 scanned ID to 1,000 units needs about 150 million weights. A 3×3 convolution with 64 filters over the photo's 3 colour channels needs 3×3×3×64 = 1,728 — five orders of magnitude fewer, and it works on any input size.

The two assumptions that buy that: locality, since a tamper seam is made of adjacent pixels, so a unit does not need to see the whole image; and parameter sharing, since a seam detector is useful everywhere, so the same nine weights apply at every position.

And the consequence worth stating: with far fewer parameters and a correct prior, a CNN generalises from far less data than a dense network could. That is the inductive-bias argument in its most concrete form.

MIDHow many parameters are in a 3×3 conv layer with 64 input and 128 output channels?
3 × 3 × 64 × 128 + 128 = 73,856 — kernel area times input channels times output channels, plus one bias per output channel.

This extends the 31.3 formula to a deeper layer of the same network, where the running channel count has grown from 3 (the raw RGB scan) to 64. Each filter here spans all 64 input channels, so a "3×3 filter" is really a 3×3×64 volume — 576 weights; there are 128 such filters; plus 128 biases.

Two things worth adding, because they are what the question is really probing:

  • Parameter count is independent of input resolution. The same layer applies to a 32×32 or a 512×512 scan. What changes with resolution is the compute and the activation memory, not the parameters — and activation memory is usually what actually limits your batch size.
  • FLOPs are a different question. Roughly output positions × 3 × 3 × 64 × 128 multiply-adds. At 56×56 output that is around 231 million MACs for this one layer. Parameters and compute must be reasoned about separately, which is exactly the point behind depthwise separable convolutions in 31.8.
MIDWhy stack two 3×3 convolutions instead of using one 5×5?
Same receptive field, fewer parameters, and an extra non-linearity in between.

Two stacked 3×3 layers see a 5×5 region of the input (31.5), so their receptive field matches. But per channel pair, two 3×3s cost 18 weights against a 5×5's 25 — about 28 % fewer — and the gap widens for 7×7, where three stacked 3×3s cost 27 against 49.

The more interesting benefit is the non-linearity between them. A 5×5 layer is one linear operation followed by one activation. Two 3×3 layers give two activations, so the composite function is strictly more expressive over the same spatial extent. That was VGG's core finding and it is why 3×3 became the universal default.

The boundary I would add: this is not unconditional. Very large kernels came back in ConvNeXt and RepLKNet, where 7×7 depthwise convolutions work well — because a depthwise kernel's cost grows much more slowly with area (31.8), so the parameter argument that killed large kernels no longer applies. The rule was a consequence of the cost model, and the cost model changed.

SENIORIs a CNN translation invariant?
No — convolution is equivariant, not invariant (31.6). Shift the input and the feature map shifts identically. Invariance is approximated later, by pooling and by global average pooling.

How invariance actually gets built, concretely: max pooling gives a little, since the max over a 2×2 window often survives a one-pixel shift, as in 31.4's worked example. Stacking many of those accumulates more. Global average pooling at the head gives full invariance to translation by collapsing all spatial positions. So a classification CNN is equivariant in its body and invariant at its head, by construction.

The important caveat, from Azulay and Weiss and from Zhang's work on anti-aliasing: modern CNNs are much less shift-invariant than people assume. Strided convolutions and pooling violate the Nyquist criterion, so shifting an image by one pixel can change the prediction substantially. Blurring before downsampling — anti-aliased pooling — measurably improves it. That is a good detail to have: the textbook property is approximate, and in a way that has been measured and partly fixed.

And the honest note about the rest: CNNs are not invariant to rotation or scale at all. Those come from data augmentation, not architecture, which is why augmentation is doing more work than it is usually credited with.

MIDWhat is a 1×1 convolution for?
It mixes channels at each spatial position without touching the neighbourhood — a cheap way to change channel count, and exactly a per-position dense layer (31.7).

Three jobs it does:

  • Dimensionality reduction. The bottleneck pattern in ResNet: 1×1 down to 64 channels, do the expensive 3×3 there, 1×1 back up to 256. The 3×3 then operates on a quarter of the channels, which is where most of the saving comes from.
  • Channel mixing. A depthwise convolution processes each channel separately and never combines them; the 1×1 that follows is what does the combining. That two-step split is the whole of depthwise separable convolution (31.8).
  • Adding non-linearity cheaply. Each 1×1 comes with an activation, so it increases depth and expressiveness for very little compute.

The connection worth drawing: a 1×1 convolution over C channels is a dense layer applied independently at every position with shared weights — module 10.6's Xw run per pixel. Which means a transformer's position-wise feed-forward network is the same operation on a sequence instead of a grid. Noticing that unification is the kind of thing that reads as real understanding rather than memorisation.

SENIORVision transformers beat CNNs. Does that mean convolution was a mistake?
No — it means a strong inductive bias is worth a lot when data is scarce and becomes a constraint when data is abundant. ViTs beat CNNs above a data threshold and lose below it, which is exactly what that trade predicts.

The empirical shape, from the original ViT paper: trained on ImageNet-1k alone, ViT underperforms a comparable ResNet. Pretrained on ImageNet-21k it draws level. On JFT-300M it wins clearly. The architecture did not change; the data did.

Why: a CNN has locality and translation equivariance hard-coded (31.1, 31.6). Those are true facts about images, given for free, and they save an enormous amount of data. A ViT assumes almost nothing — self-attention (a mechanism, covered in full in module 32, that lets any image patch attend directly to any other patch from the first layer) — so it must learn that locality matters. With enough data it learns something better than the hand-coded prior, including long-range relationships a CNN can only reach after many layers of receptive-field growth (31.5). With too little data it never gets there.

The complication that makes this a good answer rather than a neat one: ConvNeXt took a plain ResNet and applied the training recipe that came with transformers — AdamW, heavy augmentation, long schedules, LayerNorm, larger depthwise kernels — and matched ViT performance. So a substantial part of the apparent architectural gap was actually a training-recipe gap. The honest summary is that at scale, architecture matters less than data, compute and recipe — and that hybrid designs like Swin, which reintroduce locality into attention, are what most production vision systems actually use.

What I would take from it for an LLM role: the same argument runs in reverse for language. Transformers won there earlier and more decisively because text data was already abundant and because the useful dependencies genuinely are long-range, so a locality prior would have been a false assumption rather than a helpful one.
