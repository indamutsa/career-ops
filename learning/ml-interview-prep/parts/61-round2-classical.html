Part F · Interview rounds · Module 61

Round 2 · Classical ML The round most candidates under-prepare because they assume it is beneath a research role. It is not — fraud, tabular data and imbalanced problems are where a lot of applied work actually lives, and a shaky answer here reads as inexperience.

How to run this round

45 minutes. Rapid-fire out loud, then the deep questions, then the case. The case is the one that decides the round — treat it as a conversation, ask clarifying questions, and state your assumptions before you answer.

Rapid fire — 20 seconds each

BASICBias versus variance?
Bias is error from a model too simple to capture the pattern; variance is error from a model so flexible it fits the noise. High bias underfits, high variance overfits, and total error is bias² + variance + irreducible noise.
MIDBagging versus boosting?
Bagging trains many models in parallel on bootstrap samples and averages them — it reduces variance. Boosting trains sequentially, each model fixing its predecessor's errors — it reduces bias. Random forest is bagging; XGBoost is boosting.
MIDWhy does random forest sample features as well as rows?
Because bootstrap sampling alone leaves the trees correlated — one dominant feature is chosen first by nearly every tree. Averaging correlated models barely reduces variance, so restricting the features at each split decorrelates them, which is where most of the gain comes from.
MIDWhat does gradient boosting actually fit?
Each new tree fits the negative gradient of the loss with respect to the current predictions — the pseudo-residuals. For squared error that is literally the residual; for other losses it is the generalisation of one.
BASICL1 versus L2 regularisation?
L1 drives coefficients to exactly zero, so it selects features; L2 shrinks them all smoothly without eliminating any. Geometrically it is the diamond's corners versus the circle's smooth edge.
MIDWhat is the kernel trick?
The dual SVM depends on the data only through inner products, so you can replace the inner product with a kernel that computes it in a higher-dimensional space — without ever constructing the coordinates in that space.
MIDWhy is Naive Bayes "naive", and why does it work anyway?
It assumes the features are conditionally independent given the class, which is essentially never true. It works because classification only needs the right argmax, not calibrated probabilities — and the errors from the false assumption often do not change which class wins.
BASICPrecision versus recall?
Precision: of the ones I flagged, how many were right. Recall: of the ones that were real, how many did I catch. Precision is the cost of false alarms, recall the cost of misses.
SENIORROC-AUC or PR-AUC under class imbalance?
PR-AUC. ROC's false-positive rate has the huge negative class in its denominator, so thousands of false positives barely move it — the curve looks excellent while the precision is unusable. PR-AUC uses precision, which has the flagged set in the denominator, so it reflects what an analyst actually experiences.
MIDWhat is calibration, and why care?
A model is calibrated when the events it assigns 5 % to happen 5 % of the time. You need it whenever the score feeds a cost calculation or a human decision — ranking metrics like AUC are completely blind to it.
MIDHow do you pick a classification threshold?
From the cost matrix, not from 0.5. Choose the threshold that minimises expected cost given the cost of a false positive and a false negative — or that hits a fixed operational constraint, like the number of alerts your review team can handle per day.
MIDWhat is data leakage? Give two examples.
Information in training that would not be available at prediction time. Examples: a feature computed after the outcome (a chargeback count that includes this transaction's chargeback), and scaling or imputing using statistics computed over the whole dataset before splitting.
MIDWhen must cross-validation not be random?
Whenever there is structure the split must respect: time series need a forward-chaining split; grouped data — multiple rows per customer — needs group-wise splitting, or the same customer appears on both sides and the score is inflated.
MIDSMOTE — when would you use it?
Rarely, and cautiously. It synthesises minority points by interpolation, which can invent implausible examples in the region between classes. Class weights or threshold adjustment usually work as well with less risk, and any resampling must happen inside the cross-validation fold, never before it.
SENIORSHAP versus permutation importance?
SHAP gives per-prediction attributions with additive consistency guarantees, from cooperative game theory. Permutation importance is a global measure: shuffle a feature and see how much performance drops. Both are distorted by correlated features — permutation by evaluating impossible input combinations, SHAP by splitting credit between correlated features.
MIDWhy does k-means need k, and how do you choose it?
Because it minimises within-cluster variance, which decreases monotonically with k — so the objective alone can never choose it. Use the elbow, the silhouette score, or a downstream task metric; and remember k-means assumes spherical clusters of similar size, so a bad fit may be the algorithm rather than the k.
MIDWhat is an isolation forest doing?
Splitting the data at random and measuring how few splits it takes to isolate a point. Anomalies are isolated quickly because they sit apart. It is unsupervised, so it finds "unusual", which is not the same as "fraudulent".
SENIORWhy do gradient-boosted trees still beat neural nets on tabular data?
Trees handle mixed types, missing values and irrelevant features natively, are invariant to monotone transformations of the inputs, and their axis-aligned splits match how tabular features actually behave. Neural nets need far more data and preprocessing to reach the same place. Grinsztajn et al. showed the gap is real and not just tuning effort.

Deep questions — 5 minutes each

SENIORExplain the bias–variance decomposition and where it stops being the right story.
Expected squared error decomposes into bias² + variance + irreducible noise, and classically you trade one against the other. But the double-descent phenomenon shows the classical U-curve is not the whole picture — past the interpolation threshold, test error falls again as capacity grows.

The decomposition: over random draws of the training set, bias is how far the average prediction sits from the truth, variance is how much the prediction moves between draws, and the noise floor is irreducible. More capacity lowers bias and raises variance; regularisation does the reverse.

Where it breaks. The classical story predicts that a model with far more parameters than data points must overfit catastrophically. Modern deep networks have orders of magnitude more, interpolate the training set exactly, and still generalise. Belkin et al.'s double-descent curve shows test error rising to a peak at the interpolation threshold and then falling again as capacity keeps growing.

Why, as best the field understands it: among the many parameter settings that fit the data exactly, gradient descent finds particular ones — an implicit regularisation toward low-complexity solutions. Capacity counted in parameters is simply the wrong measure of the effective complexity of what SGD actually selects.

What I take from it practically: the trade-off remains the right mental model for classical models and small data — it is why bagging and boosting attack different terms — but "too many parameters" is not by itself an argument against a model. The empirical validation curve decides, not the parameter count.

SENIORHow would you handle a 0.1 % positive rate?
Do not fix the imbalance — fix the evaluation and the threshold. Use PR-AUC and cost-based thresholding, class weights rather than resampling, and stratify every split. The imbalance is a property of the problem, not a defect in the data.

Evaluation first, because everything else depends on it. Accuracy is meaningless — predicting "never" scores 99.9 %. Use PR-AUC, precision at fixed recall, or recall at a fixed alert budget, and stratify the folds so every fold contains positives.

Then the threshold, from a cost matrix. If a missed fraud costs €200 and a false decline costs €5 in goodwill and friction, the optimal threshold follows from those numbers, not from 0.5. Often the real constraint is capacity: the review team handles 500 alerts a day, so the threshold is whatever produces 500.

On the model side: class weights or scale_pos_weight in the gradient-boosting library — same effect as resampling without duplicating data or inventing points. I would try plain weighting before SMOTE, and if I did resample, strictly inside the fold.

What usually matters more than any of that: features. At a 0.1 % rate the signal is in behaviour over time — velocity, deviation from the entity's own history, graph relationships between cards, devices and merchants. Better features move this problem much further than better classifiers do.

And the framing I would end on: in the extreme, treat it as anomaly detection or a hybrid — rules for known patterns, a supervised model for learned ones, unsupervised detection for novel ones. Three layers with different failure modes beat one model asked to do everything, and that layering is what real fraud stacks actually look like.

SENIORA stakeholder asks why the model declined a specific customer. Answer them.
Give the top contributing factors for that decision in plain language with their direction and magnitude — from SHAP on that single prediction — then be explicit that these are correlations the model relies on, not a causal account of that person.

What I would actually say: "The score was driven mainly by three things: the transaction was 12× this card's usual amount, it was the fourth attempt in ten minutes, and the device had not been seen before. Together those pushed it from a baseline 0.4 % risk to 22 %, which is above our decline threshold of 15 %."

Why local, not global. Global feature importance answers "what does the model generally use", which is not what was asked. The question is about one decision, so it needs a local attribution — SHAP values for that row, which have the useful property of summing to the difference between the prediction and the base rate. That additivity is what makes the sentence above honest.

The caveats I would state without being asked, because omitting them is how explanations mislead: SHAP explains the model, not the world — it says what the model used, not why the customer behaved that way. Correlated features share credit, so a listed factor may be standing in for another. And a different explanation method can rank the factors differently, which is uncomfortable but true.

Then the operational half, which is usually what the stakeholder actually needs: there must be a review path and an appeal route (module 55), the explanation must be stored with the decision, and the wording given to the customer should be less specific than the wording given internally — a precise decline reason is a probe an adversary can use to map the boundary.

The case — 15 minutes

Talk through this out loud, end to end

"We have five years of card transactions, roughly 0.2 % labelled fraudulent, with labels arriving as chargebacks up to 60 days later. Build me a model."

The structure to hit: clarify the objective and the cost of each error type → split temporally, never randomly → build features from the entity's own history with a point-in-time join → start with gradient boosting as the baseline → evaluate with PR-AUC and at the operating threshold, sliced by segment → pick the threshold from cost or from review capacity → deploy shadow then canary → monitor with PSI and prediction drift because labels are 60 days late → retrain on a schedule, with a randomised holdout to keep the feedback loop honest.

Marks are lost for jumping to the model choice first, for a random train/test split, for reporting accuracy or plain AUC, for treating 0.5 as the threshold, and for having no answer to "how will you know it is still working next month?".
