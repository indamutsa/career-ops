Position — the thing attention throws away

WhatPosition information tells attention where each token occurs, not only what it contains.
WhyWithout it, reordering identical token vectors merely reorders the outputs; word order has no learned meaning.
Where in MLChoose a position scheme when defining a model’s context length and extrapolation behaviour.
token identity + position information → order-aware queries and keys → order-sensitive attention

Self-attention is permutation-equivariant: shuffle the input tokens and the outputs shuffle identically. It computes a set operation, not a sequence operation. "Dog bites man" and "man bites dog" would be indistinguishable. So position must be injected explicitly — one of the two things the transformer lost when it deleted recurrence.

Self-attention applies the same query, key and value projections at every position. If the two token vectors swap rows, the score matrix swaps the corresponding rows and columns, and the output rows swap too. This property is permutation equivariance: reorder the input and the same reorder appears at the output. A positional signal breaks that symmetry.

Interview takeawayAttention knows token content but not sequence order; positional information breaks that symmetry, usually inside the query–key comparison.

The components

WhatEmbeddings create the initial token state; normalisation stabilises it; attention and the FFN add new information to the residual stream.
WhyEach component solves a different constraint while preserving the same vector width between blocks.
Where in MLUse this component map when reading model configurations, estimating parameters or diagnosing training stability.
token ID → embedding + position → residual stream → norm → attention → residual add → norm → FFN → residual add
Token embedding basic

A lookup table mapping each vocabulary ID to a d-dimensional vector. Vocab × d parameters — often 100k × 4096, so hundreds of millions before any layer exists.

The unembedding at the output is the mirror image, and is frequently the same matrix transposed — weight tying, which saves a lot of parameters and usually helps small models.

Residual stream senior

The running d-dimensional vector per token that every block reads from and adds to.

The framing that mechanistic-interpretability work uses: layers communicate by writing into subspaces of a shared bus. It explains why you can insert or ablate a layer and often get a degraded-but-functional model.

LayerNorm mid

Normalise each token's vector to zero mean and unit variance across its features, then scale and shift with learned γ and β.

Per token, not per batch — so it is independent of batch size and works identically at training and inference. That is exactly why sequence models use it and BatchNorm is unusable here (module 30.5).

RMSNorm mid

Drop the mean-centring and the bias: divide by the root-mean-square and scale.

It removes mean-centring and therefore one reduction over the feature axis. Many modern decoder models use it, but its quality and runtime effect depend on the architecture, kernel and hardware.

Pre-norm vs post-norm senior

Post-norm (original): x = Norm(x + Sublayer(x)). Pre-norm (common in modern decoder models): x = x + Sublayer(Norm(x)).

Pre-norm keeps the residual path completely clean — no normalisation sits on it — so gradients have a direct additive path to early layers and training is generally more stable. The required warmup still depends on scale, initialisation and optimiser settings.

Feed-forward network (FFN) mid

Two linear layers with a non-linearity between, applied identically at every position: expand d → 4d, activate, project 4d → d.

Attention is the meeting where tokens exchange information. The FFN is each token going back to its desk and thinking about what it heard, alone.

Roughly two thirds of the parameters in a standard block. Also where factual knowledge appears to live — the key-value-memory result (Geva et al.).

GELU and SwiGLU mid

GELU is a smooth ReLU. SwiGLU adds a gate: one projection is multiplied elementwise by a Swish-activated second projection.

SwiGLU needs three weight matrices, so the hidden size is cut to about ⅔·4d to keep the parameter count level. If you count parameters assuming 4d on a Llama- style model, you will be wrong by a third.

RoPE — rotary position embedding senior

Rotate each 2-dimensional pair of the query and key vectors by an angle proportional to the token's position.

Because a dot product of two rotated vectors depends only on the difference of the angles, absolute rotations produce relative position information for free — which is the property you actually want, and it needs no extra parameters.

Interview takeawayThe residual stream is the shared state: embeddings initialise it, norms condition each read, and attention plus the FFN write additive updates.

Questions

BASICWalk me through a transformer block.
Two sublayers, each wrapped in a residual connection with a pre-norm: multi-head self-attention, then a position-wise feed-forward network. Stack that L times between an embedding layer and an output projection.

In order:

  1. Normalise the incoming residual stream (LayerNorm or RMSNorm).
  2. Multi-head self-attention — each token gathers information from the other tokens it is allowed to see.
  3. Add the result back to the residual stream.
  4. Normalise again.
  5. FFN — expand to 4d, apply GELU or SwiGLU, project back to d, independently at every position.
  6. Add back to the residual stream.

The division of labour is the part worth stating explicitly: attention moves information between positions; the FFN processes information within a position. Attention is the only place tokens interact at all — remove it and you have a per-token MLP.

Around the stack: token embeddings plus position information at the input, a final norm, and a projection to vocabulary logits at the output, often tied to the input embedding matrix.

BASICWhy do transformers need positional encodings when RNNs do not?
Self-attention is permutation-equivariant — it treats the input as a set. An RNN gets order for free from processing tokens one at a time; a transformer processes them all at once and must be told.

The proof is short: attention computes weights from dot products between token vectors. Permute the inputs and you permute the rows and columns of the score matrix identically, so the outputs permute with them. Nothing anywhere depends on where a token sits. Without position, "dog bites man" and "man bites dog" have identical representations.

That is the price of removing recurrence. The RNN's sequential loop encoded order implicitly; the transformer bought parallelism and had to pay it back explicitly.

The interesting complication: a decoder-only transformer is not fully permutation-equivariant, because the causal mask is itself position-dependent — token 5 sees five tokens, token 50 sees fifty. That leak is enough that "NoPE" models with no positional encoding at all learn position competently. It is a genuine research result and a good thing to know, though explicit schemes still work better in practice.

SENIORSinusoidal, learned, RoPE, ALiBi — what is the actual difference?
They differ on whether position is absolute or relative, whether it is added to the embedding or applied inside attention, and whether the model can handle sequences longer than it was trained on. RoPE won because it is relative, parameter-free, and interpolable.

Sinusoidal — fixed sin/cos at geometrically spaced frequencies, added to the input embedding. Parameter-free, and the authors hoped the linear relationship between position encodings would let the model extrapolate. It mostly does not: quality degrades quickly past the training length.

Learned absolute — one trainable vector per position. Simple, slightly better in-distribution, and hard-capped: position 2049 in a 2048-trained model has no vector at all.

RoPE — rotate query and key vectors by an angle proportional to position, inside the attention computation rather than at the input. The key property: the dot product between a rotated query at position m and a rotated key at position n depends only on (m − n). You apply absolute rotations and get relative position for free, with zero added parameters. It also extends: position interpolation rescales positions into the trained range, and NTK-aware or YaRN scaling adjusts the base frequency, so an 8k model can be stretched to 128k with modest fine-tuning. That practicality is why it dominates.

ALiBi — no encoding at all; instead subtract m·|i − j| from the attention score, with a per-head slope. A learned recency bias, effectively. It extrapolates gracefully by construction, and the trade-off is that the penalty is monotonic, so a genuinely important token very far back is always fighting the bias.

The way I would summarise it: the field moved from adding position to the content vector — where it competes with semantics for the same dimensions — to expressing position as a relation between positions inside attention, which is both what the model needs and what generalises past the training length.

SENIORWhy did everyone move from post-norm to pre-norm?
Because pre-norm leaves the residual path completely unobstructed, so gradients reach the earliest layers intact. Post-norm transformers need a learning-rate warmup to train at all; pre-norm ones do not.

Post-norm: x = LN(x + Sublayer(x)). The normalisation sits on the residual path, so every backward step through a layer passes through LN's Jacobian. Over 24 or 96 layers that compounds, and the gradient at layer 1 can be orders of magnitude off.

Pre-norm: x = x + Sublayer(LN(x)). The identity path is now pure addition all the way from the output to the embedding — the same multiply-by-1 highway argument as the ResNet and the LSTM cell state.

The empirical finding (Xiong et al., 2020) is precise: post-norm has very large gradients at initialisation in the last layers, which is exactly what warmup was silently compensating for. Pre-norm can reduce sensitivity to warmup and often tolerates a larger learning rate, but it does not make a particular schedule universally safe. At the scale where a failed run costs six figures, "trains reliably" beats a small quality edge.

The honest counterpoint: well-tuned post-norm often reaches slightly better final quality, because pre-norm's residual stream grows in magnitude with depth, which somewhat diminishes what later layers can contribute. Hence the hybrids — sandwich norm, DeepNorm — that try to get both. The mainstream choice is pre-norm plus a final norm before the output projection, and the reason is training stability, not quality.

MIDWhat is the FFN for, if attention is doing the work?
Attention moves information between tokens; the FFN transforms it within a token. It is also two thirds of the parameters and appears to be where factual knowledge is stored.

The structural argument: attention's output is a weighted average of value vectors — a linear operation given the weights. Stack attention on attention with no FFN and you have very limited per-token expressiveness. The FFN supplies the non-linear, per-position processing that turns "here is what I gathered" into "here is what I conclude".

The memory argument: Geva et al. showed the FFN behaves like a key–value store — the first matrix's rows act as pattern detectors over the residual stream, and the second matrix's columns are the values written back when a pattern fires. That framing is supported by model-editing work like ROME, which changes a specific fact by editing specific FFN weights.

The cost argument, which is where this matters in practice: the FFN is 8d² of the 12d² per block. That is why mixture-of-experts targets it — replace one FFN with many, route each token to two of them, and you multiply parameters without multiplying FLOPs per token. Mixtral and DeepSeek-V3 are exactly this. Attention is left alone because every token needs it; the FFN is the part you can make conditional.

MIDHow many parameters does a 32-layer model with d_model 4096 have?
About 12·L·d² for the blocks — 12 × 32 × 4096² ≈ 6.4 billion — plus vocab × d for the embeddings, so roughly 7 B in total for a 128k vocabulary.

The breakdown per block:

  • Attention — WQ, WK, WV, WO, each d×d, so 4d². Note this does not depend on the number of heads: heads partition d, they do not add to it.
  • FFN — d×4d up and 4d×d down, so 8d².
  • Total 12d² = 12 × 16.8 M ≈ 201 M per block, × 32 ≈ 6.4 B.

Then embeddings: 128,000 × 4096 ≈ 524 M, doubled if input and output are untied. Norms and biases are in the tens of thousands — ignorable.

Two corrections worth volunteering, because they are what separates having memorised the formula from having used it:

  • With SwiGLU there are three FFN matrices, so the hidden dimension is set to about ⅔·4d to keep the count at 8d². Assume 4d with three matrices and you overcount by a third.
  • With GQA, WK and WV are smaller than d×d — with 8 KV heads against 32 query heads they are a quarter the size, so attention drops from 4d² to about 2.5d².

And the related number they usually ask next: training FLOPs ≈ 6 × parameters × tokens, and inference ≈ 2 × parameters per token. Those three formulas cover most back-of-envelope questions in this area.
